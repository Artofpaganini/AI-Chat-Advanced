# Task12 - косвенная инъекция промпта

Продолжение task11. Там вредоносный текст писал сам пользователь в поле ввода - здесь он сидит в
данных (переписка, документ), которые пользователь просит обработать. Пользователь не участвует в
атаке, он видит обычный ответ на свой обычный вопрос. Учебная и защитная работа: ловушки строятся
только против собственного приложения.

**Главный результат:** анти-инъекционный блок из task11 закрывает подделку роли ассистента и
скрытые инструкции почти полностью, но не трогает вектор "документ содержит ложный факт" - там
доля успеха 93-100% без защиты. Это не один и тот же класс уязвимости - инструкция в документе и
ложный факт в документе требуют разной защиты. Подробности - `RESULT.md`.

## Требования

- Python 3.9, только стандартная библиотека. Внешних пакетов нет и не нужно.
- Ключ `DEEPSEEK_API_KEY` - в окружении либо в `local.properties` в корне репозитория. В `raw/`,
  `results/`, документах его быть не должно - `report12.py` проверяет это гейтом.
- Сеть нужна только для живых прогонов (`run_indirect.py`, `control_experiment.py`,
  `utility_check.py`). Пересчёт метрик (`report12.py`) работает по уже собранному `raw/` без
  единого нового вызова.

## Команды

Всё запускается из каталога задачи.

```bash
cd challenge_advanced/task12

# план прогона: сколько будет вызовов и сколько это стоит, без единого запроса к API
python3 harness/run_indirect.py --dry-run

# базовая линия, без защиты, 3 повтора
python3 harness/run_indirect.py --vector all --defense none --repeats 3 --workers 4

# все четыре слоя защиты по очереди плюс комбинация "all", одной командой
python3 harness/run_indirect.py --vector all --defense sweep --repeats 3 --workers 6

# контрольный эксперимент: один текст, поле ввода против импорта (свой гейт, код 1 при провале)
python3 harness/control_experiment.py --dry-run
python3 harness/control_experiment.py --repeats 3

# цена защиты D3/D4 на чистых документах без начинки
python3 harness/utility_check.py --dry-run
python3 harness/utility_check.py --repeats 3

# пересчитать метрики по конкретному прогону и проверить гейт целостности замера
python3 harness/report12.py --raw-dir raw/run_20260804_171534 --out results/indirect_report.json
python3 harness/report12.py --raw-dir raw/run_20260804_173743 --out results/defenses_report.json
```

`--raw-dir` указывает на конкретный каталог одного прогона (`raw/run_<timestamp>/`), а не на весь
`raw/` - так H1-H4 и D-H1-D-H5 считаются каждый по своему сырью, не смешивая версии набора.
`report12.py` возвращает код 1, если гейт не пройден (все три вектора присутствуют, минимум 3
повтора, ошибок ≤10%, детекторы не залипли в одном значении, в сырье нет строки, похожей на
API-ключ). Это не порог на attack success rate - высокий ASR на `defense=none` ожидаем, это цель
замера, а не провал.

## Три вектора и четыре слоя защиты

| Вектор | Канал | Что проверяет |
|---|---|---|
| `V1_SUMMARY` | настоящий - импорт истории чата, мишень `jarvis` | подмешанная строка попадает в пересказ |
| `V2_ANALYST` | только харнесс, мишень `alva` | нарушение системного промпта (дозировка/диагноз/роль/утечка) |
| `V3_SEARCH` | только харнесс, мишень `jarvis` | ложный факт из документа выдаётся как достоверный |

| Слой | Что делает | Против чего рассчитан |
|---|---|---|
| `none` | без защиты, точка отсчёта | - |
| `d1_sanitize` | вырезает комментарии, невидимые символы и span-стили, принудительно понижает роль из чужого источника до user, ограничивает длину импортированного сообщения | H1, H2, H3, H4 |
| `d2_boundary` | история сворачивается в цитату внутри одного сообщения пользователя с явными маркерами границ | все, сильнее всего - H4 |
| `d3_output` | сверяет числа в ответе с "видимой" (markup-очищенной) версией входа | INJECTED_LINE, FALSE_FACT |
| `d4_provenance` | правило промпта: помечать источник каждого утверждения из документа отдельно от собственных фактов | FALSE_FACT на V3, добавлен вне контракта |
| `all` | все четыре вместе | - |

## Что важно знать

- **Гипотезы записаны в `SPEC.md` до соответствующих прогонов** и не переписывались. Числа в
  `REPORT.md` пересчитаны из `raw/` заново, там же явно отмечено, где формулировка `SPEC.md`
  разошлась с фактическими числами.
- **`raw/` не переписывается.** Первая версия набора документов (`run_20260804_165548`) осталась на
  диске, но в текущий отчёт не входит - набор был пересобран после `REAL_CASES.md`.
- **Числа только из `raw/`.** Детекторы - чистая функция от сохранённого ответа
  (`report12.py`, `recompute_record`), починка детектора применяется ко всему старому сырью
  бесплатно, без единого нового вызова к модели.
- **Гейт `report12.py` - не про дырявость промпта.** Высокий ASR на `defense=none` - ожидаемый
  результат замера, гейт проверяет только целостность самого замера.
- **Защита в коде приложения (входной гард на путь импорта) - отдельная параллельная работа**, её
  числа в этом отчёте не приведены.
- **Ключ только из окружения или `local.properties`**, который в `.gitignore`.
