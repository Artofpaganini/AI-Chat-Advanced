# task14 - Execution loop с проверкой безопасности

Цикл «задача -> генерация кода -> линт -> сборка -> **проверка безопасности** -> коммит». Проверку
делает второй вызов модели со своим промптом под Android и Kotlin. Находки Critical и High возвращают
цикл на генерацию, Medium и Low пропускаются с записью в журнал, чисто - коммит. Оба вызова модели
идут через шлюз из task13.

**Главный результат:** захардкоженный ключ доступа **прошёл мимо шлюза** и был **пойман шагом проверки
безопасности** как Critical. Это измеренная разница между двумя проверками, а не предположенная: шлюз
силён на известных формах секретов, проверка - на смысле кода, и одно не заменяет другое.

**Второй результат, неудобный:** цикл вернул код на доработку и получил чистый вердикт, но
уязвимости исчезли **вместе с функциональностью** - авторизация была удалена целиком. Ни одна стадия
цикла не спрашивает, решает ли код поставленную задачу.

**Третий:** чтение кода глазами дало вчетверо больше находок, чем обе автоматические проверки вместе.

## Команды

```bash
# шлюз из task13
python3 challenge_advanced/task13/harness/gateway_server.py --port 8091 --rate-limit 60

# сервер цикла
python3 challenge_advanced/task14/harness/loop_server.py --port 8092

# план прогона без единого вызова
python3 challenge_advanced/task14/harness/loop_server.py --dry-run --task "сохрани токен авторизации"

# прогон задачи
curl -sN -X POST http://127.0.0.1:8092/loop/run \
  -H "Content-Type: application/json" \
  -d '{"task":"сохрани токен авторизации","max_iterations":3}'

# состояние и история
curl -s http://127.0.0.1:8092/loop/health
curl -s "http://127.0.0.1:8092/loop/history?limit=5"
```

Из приложения: настройки -> «Inference Mode» -> **«Цикл генерации кода»**. Дальше любое сообщение в
чате считается задачей для цикла, стадии растут в пузыре ответа по мере работы.

## Что важно знать

**Вердикт «чисто» не означает «код чист».** В одном прогоне проверка нашла отсутствие таймаутов на
первой итерации, а на третьей вернула «находок нет» - при том что таймаутов в коде по-прежнему не
было. Одиночный чистый результат недостоверен.

**Генератор не видит проект.** На вход генерации уходит 400-1100 токенов: задача и системный промпт,
ни строки существующего кода. Отсюда два следствия. Хорошее - он не наследует дефекты проекта: в
проекте локальные адреса по `http`, а он написал `https`. Плохое - он не встраивается в проект, и весь
сгенерированный код никем не вызывается.

**Задача «добавь логирование всех запросов» на этом стенде невоспроизводима.** Логирование по смыслу
добавляется к существующему коду, а генератор пишет новый изолированный файл. Пять прогонов подряд не
дошли до проверки. Это не провал проверки и не ошибка предсказания, а отсутствие сценария.

**Слияние находок между попытками проверено только офлайн.** За оба замера повтор сработал один раз,
и случай, ради которого слияние писалось - когда первая попытка нашла больше второй - не встретился.
