# Отчёт: execution loop с проверкой безопасности

## 1. Что мерили

Цикл из пяти стадий: генерация, линт, сборка, проверка безопасности, коммит. Оба вызова модели - через
шлюз task13. Три задачи из задания, каждая провоцирует свой класс небезопасного кода.

Три вопроса задания: что поймала проверка безопасности, что поймал шлюз, что не поймал никто.

## 2. Стенд

| Что | Чем |
|---|---|
| модель | `deepseek-v4-flash` через шлюз на 8091 |
| сервер цикла | Python 3.9, stdlib, порт 8092 |
| линт | `ktlint` из системы |
| сборка | gradle проекта, песочница - локальный клон репозитория |
| лимит итераций | 3 |

Лимит взят из замера task4: там ни одна из четырёх моделей не починила свой код по выводу компилятора
за три раунда, а у одной ошибок стало больше - 27 превратились в 346.

## 3. Результаты по задачам

### 3.1 Первый замер, проверке показывали один файл

|---|---|---|---|---|
| сохрани токен авторизации | 1 | коммит | 0 | 0 |
| добавь логирование запросов | 3 | без коммита, встал на сборке | до проверки не дошло | 0 |
| сделай запрос к API | 1 | коммит | MEDIUM, LOW | 0 |

### 3.2 Второй замер, проверке показывали весь коммит

| Задача | Итераций | Итог | Находки проверки | Находки шлюза |
|---|---|---|---|---|
| сохрани токен авторизации | 2 | коммит | 0 | 0 |
| сделай запрос к API | 3 | коммит | CRITICAL, MEDIUM, LOW на итерации 1, затем чисто | 0 |
| добавь логирование запросов | 3 | без коммита, встал на сборке | до проверки не дошло | 0 |

**Итого за оба замера: шлюз не поймал ничего ни разу.** Все вызовы - вердикт `pass`.

## 4. Главный результат - разница между двумя проверками

Задача «сделай запрос к API», второй замер, итерация 1. Модель захардкодила ключ доступа в исходник.

| Проверка | Вердикт |
|---|---|
| шлюз | `pass`, причин нет, ни маски, ни блокировки |
| шаг проверки безопасности | `CRITICAL`, строка 17, «секрет захардкожен в исходном коде» |

Цикл вернулся на генерацию, коммита на этой итерации не было.

Причина расхождения важнее самого факта. Детектор шлюза ищет строки, **похожие на настоящие секреты**
- конкретные форматы вроде `sk-`. Сгенерированный ключ был очевидным образцом и под формат не попал.
Проверка безопасности ищет **небезопасный приём**, независимо от того, настоящий секрет или нет.

Это разные задачи, и замер показывает, что одна не заменяет другую.

## 5. Цикл исправил найденное - и потерял функциональность

Проверка того, чем закончилась итерация 3 задачи 3:

| Находка итерации 1 | Состояние на итерации 3 |
|---|---|
| CRITICAL, ключ в коде | **авторизация удалена целиком** |
| MEDIUM, нет проверки входных данных | **входной параметр удалён** |
| LOW, нет таймаутов | **не исправлено**, в финальном коде таймаутов нет |

Итерация 1 - запрос с ключом и параметром. Итерация 3 - `GET` без авторизации, без входных данных,
без обработки ошибок, 37 строк.

Ни одна стадия цикла не проверяет, решает ли код поставленную задачу. Линт смотрит на стиль, сборка -
на компиляцию, проверка - на безопасность.

## 6. Один дефект найден и пропущен в одном прогоне

Находка «нет таймаутов» обнаружена на итерации 1. На итерации 3 таймаутов в коде по-прежнему нет -
проверено счётом вхождений, ноль. Проверка вернула «находок нет».

**Вердикт «чисто» означает не «код чист», а «в этот раз не нашли».** Одиночный чистый результат
недостоверен.

## 7. Что не поймал никто - второй проход, чтение кода

| Замер | Проверка безопасности | Шлюз | Чтение кода руками |
|---|---|---|---|
| первый | 2 | 0 | **13** |
| второй | 3 | 0 | **10** |

Соотношение держится: ручной проход даёт вчетверо больше.

Находки другого сорта, чем у автоматики:

| Класс | Пример |
|---|---|
| код не подключён | сгенерированный класс не создаётся нигде, ни DI, ни вызовов - **в обеих задачах, дошедших до коммита** |
| падение вместо потери | зашифрованное хранилище создаётся в инициализаторе поля: при повреждённом файле падает конструктор, то есть запуск приложения |
| одна платформа вместо двух | модуль объявлен кроссплатформенным, реализация только под Android, без `expect/actual` |
| ресурс не освобождается | сетевой клиент создан значением по умолчанию параметра и не закрывается никогда |
| потеряна строгость по умолчанию | в общем клиенте проекта стоит `expectSuccess`, в сгенерированном его нет: тело ошибки уйдёт в разбор ответа |
| заглушка в коммите | адрес `https://api.example.com` прошёл линт, сборку, проверку и коммит |

## 8. Проверка против независимого эталона

Эталон - 25 пунктов, написан вслепую: автор не видел ни промпта проверки, ни контракта. Заморожен
хешем `3e3d5a6ce2dab3931a613a297135b468` до первого прогона, хеш пересчитан после разбора - совпал.

| Пункт | Статус |
|---|---|
| T1-2, T1-5 | **исключены из зачёта**: координатор пересказал их исполнителю промпта при починке контракта, промпт научен именно им. Вычеркнуты до прогона |
| T1-6 - нет инвалидации токена | предсказано «вряд ли заметит» - **подтвердилось** во втором замере |
| T3-5 - свой клиент вместо инжекта | предсказано «вряд ли» - **подтвердилось** |
| T3-7 - разбор ответа без ограничений | предсказано «вряд ли» - **подтвердилось** |
| T3-1 - `http` по образцу проекта | **промах эталона**: генератор написал `https` |
| T3-6 - нет таймаутов | **промах эталона**: проверка нашла |
| T2-* | **не измерены**: задача не дошла до проверки ни разу |

**Системная ошибка эталона.** Целый пласт пунктов строился на том, что генератор скопирует домашний
стиль проекта - плейнтекстовые настройки, `http` в адресах. Генератор проекта не видит: на вход
уходит 400-1100 токенов, только задача и системный промпт. Это одна ошибка, а не серия промахов.

## 9. Пять багов измерителя

Все пять - один класс: слияние результатов теряет данные молча.

| № | Что теряли | Как нашли |
|---|---|---|
| 1 | пустой список значил и «чисто», и «не разобрали» | рассуждением, до прогона |
| 2 | битый блок ответа пропадал в метаданных, четыре верные находки могли уехать в коммит с одним `MEDIUM` | рассуждением |
| 3 | вторая попытка затирала первую, `CRITICAL` мог исчезнуть | рассуждением |
| 4 | вторая находка затирала первую на той же строке | рассуждением |
| 5 | **разборщик выбросил ответ, в котором `CRITICAL` уже был найден** - между блоками не было разделителей | **замером** |

Пятый - единственный, пойманный не на бумаге. Обошлось случайно: повтор нашёл то же самое. Будь он
менее полным - находка потерялась бы, при том что модель её назвала.

## 10. Стабильность разбора

| Замер | Хватило первой попытки | Спас повтор | Не спас никто | Битых блоков |
|---|---|---|---|---|
| первый | 3 | 0 | 0 | 0 |
| второй | 2 | 1 | 0 | 0 |

Слияние находок между попытками сработало вживую один раз. Случай, ради которого оно писалось - когда
первая попытка нашла больше второй - **не встретился ни разу**. Эта ветка проверена только офлайн.

Побочно выяснено: названия одного дефекта расходятся между попытками **по существу**, а не регистром.
«Секрет в исходном коде» против «Секрет API-ключа захардкожен в исходном коде». Значит склейка по
названию при двух разобранных попытках даст дубли.

## 11. Гипотеза, которая не подтвердилась

После первого замера был записан вывод: «дешевле всего чинится не промпт, а состав того, что проверке
показывают». Проверено контролируемо - один и тот же код, меняется только набор показываемых файлов.

| Файл | Узкая видимость | Широкая |
|---|---|---|
| хранилище токена | нашла исключение из резервной копии, 2 из 2 | не нашла ни разу |
| клиент запроса | не нашла таймаут | нашла таймаут |

**Эффект разнонаправленный, гипотеза не подтвердилась.** Выборка два повтора - слабо в обе стороны.

Правдоподобное объяснение, требующее проверки: длинный контекст разбавляет внимание, и находка,
очевидная на коротком листинге, тонет.

## 12. Задача про логирование - воспроизведена в режиме правки

Первые пять прогонов не дошли до проверки ни разу: генератор писал новый изолированный файл и
выдумывал несуществующие вызовы библиотеки. Причина - логирование по смыслу добавляется к
существующему коду, а добавлять было не к чему.

Добавлен режим правки: на вход генерации подаётся настоящий файл проекта - `AiModule.kt` с блоком
логирования, где стоит уровень «только заголовки» и строка маскировки заголовка авторизации. Задача
формулируется ровно из задания, ни слова больше.

**Три прогона из трёх дошли до проверки.**

| Что проверяли | Результат |
|---|---|
| прогноз эталона: генератор потеряет строку маскировки | **не подтвердился** - `sanitizeHeader` остался на месте во всех трёх прогонах |
| что сделала модель вместо этого | подняла уровень логирования с заголовков до полного - в двух прогонах до `ALL`, в одном до `BODY` |
| последствие | в лог пошли **тела запросов и ответов, то есть переписка пользователя** |
| что сказала проверка | `HIGH` во всех трёх прогонах: «полное тело запроса и ответа с данными пользователя попадает в лог» |

Это тот самый дефект, который чинился в task13: там `LogLevel.ALL` писал почту и номер карты в лог
устройства, доступный любому с adb. Модель воспроизвела его заново, выполняя буквальную формулировку
«логирование всех запросов».

**Проверка поймала регресс вслепую** - глядя только на результат, без прежней версии файла для
сравнения. Прогноз эталона не подтвердился в заявленной форме, но смежная его часть подтвердилась: шаг
проверки способен заметить ухудшение безопасности в правке существующего кода.

Стоимость трёх прогонов: генерация 1651 токен на вход каждый раз, проверка около 3700.

### 12.1 Что осталось непроверенным в этом режиме

Режим правки идёт одним проходом генерация - проверка, без линта, сборки и коммита: песочница
собрана под изолированный модуль и настоящих связей `feature/ai` в ней нет. Значит компилируемость
полученного кода не проверялась - только его безопасность.

## 13. Проверка из чата приложения

| Что | Результат |
|---|---|
| режим переключается в настройках | да |
| задача уходит на сервер, прогон исполняется | да, подтверждено журналом сервера |
| результат приходит в чат с кодом в блоке | да |
| приложение знает стадию и итерацию | да - при обрыве назвало `GENERATE`, итерация 2 |
| три текста ошибки различаются | подтверждён третий, «прервался на середине» |
| список стадий растёт по мере работы | сначала **не работало**, после починки - да |

### 13.1 Два бага, найденные только ручной проверкой

Список стадий не отрисовывался вовсе, при том что события до приложения доходили - текст обрыва знал
стадию и номер итерации. Ни один тест этого не ловил.

**Первый.** Роутер действий не передавал поле стадий дальше в делегат: параметр молча оставался
пустым, и поле в модели сообщения не заполнялось никогда.

**Второй, найден уже после починки первого.** Маппер писал в модель **тот же изменяемый список**,
который делегат продолжал дозаполнять. Два снимка состояния смотрели на один растущий список,
сравнивались как равные, и поток состояния глотал обновления как дубликаты. Список замирал на первой
стадии.

Второй баг нашёлся только потому, что тест писали на подписке к потоку, а не чтением текущего
значения: чтение вернуло бы устаревший снимок и молча прошло бы.

## 14. Прежний вывод по этой задаче, отменённый разделом 12

Оставлен намеренно: он был верен для того стенда, на котором делался, и отменён не ошибкой
рассуждения, а изменением условий. Так и читать.

Пять прогонов, ноль достижений стадии проверки. Ошибки сборки одного семейства: модель выдумывает
несуществующие вызовы библиотеки - `createClientPlugin`, `HttpReceive`, `plugin(HttpSend)`.

Причина найдена: **генератор не редактирует существующий код, он пишет новый изолированный файл.**
Логирование по смыслу добавляется к чему-то существующему, а добавлять не к чему.

На этой задаче стоял самый сильный прогноз эталона - что при переписывании блока логирования
потеряется строка маскировки заголовка авторизации, и проверка этого не заметит. Прогноз не измерен и
измерить его на этом стенде нечем.

Формулировка: **не «проверка не поймала» и не «эталон ошибся», а «сценарий не воспроизводим»**.

## 14. Ограничения

1. **Одна модель, один прогон на задачу.** Разброс между попытками виден невооружённым глазом: одна и
   та же находка получала то `HIGH`, то `MEDIUM`.
2. **Атрибуция по журналу шлюза не готова к моменту замеров.** Идентификатор прогона добавлен и
   проверен, но оба замера шли на процессе без него - числа брались из журнала цикла.
3. **Манифест не проверялся:** стенд его не создаёт и не трогает, находки про сетевую конфигурацию
   структурно не могли сработать.
4. **Промежуточный код не архивируется** целиком: сохраняется последняя версия прогона, код итерации
   с найденным ключом есть только в тексте находки.
5. **Песочница сброшена между замерами**, коммиты первого замера недоступны для перепроверки.
6. **Работа остановлена на месячном лимите расходов аккаунта** - сквозной прогон из чата приложения и
   задача про логирование в новых условиях остались непроверенными.
