# Как пользоваться локальным ассистентом

Практическая инструкция: включить, работать, выключить, починить.
Теория и цифры - в остальных файлах папки. Здесь только кнопки.

Что где крутится:

| Слой | Чем | Роль |
|---|---|---|
| Движок | Ollama на `localhost:11434` | держит модели, отдаёт API |
| Чат-модель | `qwen3-coder:30b` | чат, объяснения, скелеты |
| Автокомплит-модель | `qwen2.5-coder:1.5b-base` | подсказки в редакторе |
| Эмбеддер | `nomic-embed-text` | индекс кодовой базы |
| Автокомплит в IDE | плагин **Continue** | подсказки прямо в коде |
| Чат в IDE | плагин **ProxyAI** | панель диалога |

---

## 1. Быстрый старт - три шага

### Шаг 1. Поднять движок

```bash
ollama serve
```

Один раз на сессию. Команда не завершается - держит сервер. Если хочешь, чтобы работал в фоне и не
занимал терминал:

```bash
ollama serve > /dev/null 2>&1 &
```

Проверить, что жив:

```bash
curl -s http://localhost:11434/api/version
```

Ответ вида `{"version":"0.13.5"}` - значит поднят.

### Шаг 2. Прогреть модель (по желанию, убирает 6-секундную паузу на первый ответ)

```bash
ollama run qwen3-coder:30b "ok"
```

Модель загрузится в память и повисит там час (`keepAlive: 3600` в конфиге). Первый чат-запрос после
этого - четверть секунды вместо шести.

### Шаг 3. Открыть Android Studio

Всё уже настроено. Просто открой проект. Continue и ProxyAI подхватятся сами.

---

## 2. Как пользоваться в IDE

### Автокомплит (Continue)

Просто печатай код. Через ~0.25 секунды появляется серая подсказка-призрак.

- **Принять целиком** - `Tab`
- **Принять одно слово** - `Cmd+ →`
- **Отклонить** - `Esc` или продолжай печатать

Ничего нажимать для вызова не надо - подсказки идут сами по мере набора.

### Чат (ProxyAI)

- Открыть панель - иконка **ProxyAI** в правом тулбаре.
- Написать вопрос, `Enter`. Первый ответ 6-8 секунд (грузится модель), дальше ~67 токенов/с.
- Приложить текущий файл в контекст - кнопка со скрепкой / `@` в поле ввода.

Готовые действия по выделенному коду (ПКМ по выделению -> ProxyAI): Explain, Find Bugs, Refactor.

## 3. Включить / выключить

### Выключить на время (освободить 20 GB памяти, не трогая настройки)

Выгрузить модели из памяти, сервер оставить:

```bash
ollama stop qwen3-coder:30b
ollama stop qwen2.5-coder:1.5b-base
```

Память освободится сразу. Следующий запрос из IDE снова их загрузит (пауза ~6 с на первый ответ).

### Выключить движок полностью

```bash
pkill -f "ollama serve"
```

После этого ассистент в IDE отвечать не будет - плагины показывают ошибку соединения. Это нормально,
поднимется обратно шагом 1.

### Выключить только один плагин, не трогая движок

`Cmd+,` -> **Plugins** -> сними галку с **Continue** (убрать автокомплит) или **ProxyAI** (убрать чат) ->
Apply -> перезапустить IDE.

### Полностью снять из автозагрузки памяти

В обоих плагинах убери `keepAlive` / замени на короткое - тогда модель выгружается сразу после ответа.
Но каждый запрос будет ждать перезагрузку. Держать `keepAlive: 3600` удобнее, если памяти хватает.

## 4. Проверить, что всё работает

### Модель отвечает вообще

```bash
ollama run qwen3-coder:30b "напиши хеллоу ворлд на kotlin"
```

### Что реально уходит из IDE в модель

Между плагином и ollama можно поставить логгер и увидеть каждый запрос:

```bash
python3 challenge_advanced/task4/harness/proxy_log.py &     # поднимает прокси на :11435
```

Дальше в плагинах временно поменять хост `11434` -> `11435`, поработать, потом посмотреть:

```bash
tail -f challenge_advanced/task4/raw/ide_traffic.jsonl
```

Каждая строка - реальный запрос: модель, режим (`fim` = автокомплит), сколько контекста ушло.
После проверки вернуть хост на `11434` и погасить прокси (`pkill -f proxy_log.py`).

### Работает ли офлайн

Отключи Wi-Fi и задай вопрос в чате. Ответ придёт - модель локальная, интернет не нужен.

## 5. Где что настраивается

| Что менять | Файл / место |
|---|---|
| Модели, параметры, контекст для Continue | `~/.continue/config.yaml` |
| Что Continue НЕ видит в контексте | `<проект>/.continueignore` |
| Правила проекта для Continue (чат/edit) | `<проект>/.continue/rules/*.md` |
| Хост, модель, персона для ProxyAI | `Cmd+,` -> Tools -> ProxyAI |
| Язык и конвенции ответов ProxyAI | там же -> Persona / System Prompt |

После правки `config.yaml` Continue перечитывает его сам. ProxyAI - жми Apply в настройках.

## 6. Если что-то сломалось

| Симптом | Причина | Что делать |
|---|---|---|
| Плагин: «connection refused» | движок не поднят | `ollama serve` (шаг 1) |
| Первый ответ ждёт 6-8 секунд | модель грузится с диска | норма; прогрей заранее (шаг 2) |
| Автокомплит не показывается | подсказка длиннее строки, плагин её отбросил | в `config.yaml` у автокомплит-модели должен быть `stop: ["\n\n"]` - он там есть |
| Ответы на английском | ProxyAI не читает правила Continue | впиши язык в Persona ProxyAI (раздел 5) |
| ProxyAI: `IOException ... against a directory: .proxyai` | плагин читает свою служебную папку как файл | `.proxyai/` уже в `.gitignore` и `.continueignore`; перезапусти IDE |
| Панель чата Continue: «Unable to load / JCEF» | webview Continue не стартует на этой сборке Studio | это ожидаемо, чат вынесен в ProxyAI; панель Continue не открывать - см. `IDE_VERIFICATION.md` |
| Inline Edit Continue (`Cmd+I`) висит | до этого открывалась чат-панель Continue и уронила шину плагина | перезапусти IDE, панель Continue не трогай |
| Всё тормозит, мало памяти | две модели в памяти = ~20 GB | `ollama stop <модель>` для ненужной |

## 7. Запасной чат - из терминала

Если плагин ProxyAI отвалится, чат и агент есть в терминале, на том же конфиге:

```bash
# разовый вопрос
npx @continuedev/cli --config ~/.continue/config.yaml -p "объясни класс ChatViewModel"

# интерактивная сессия
npx @continuedev/cli --config ~/.continue/config.yaml
```

Тоже локально, тоже офлайн.
