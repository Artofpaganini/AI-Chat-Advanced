# Проверка живьём: что реально работает в IDE

Проверялось не «на глаз», а прокси-логгером между плагином и ollama (`harness/proxy_log.py`,
порт 11435). В логе видно, какая модель дёрнулась, с какими параметрами и сколько контекста ушло.
Сырьё - `raw/ide_traffic.jsonl`.

## Итог

| Режим | Работает | Доказательство |
|---|---|---|
| **Автокомплит в редакторе** | ✅ | `POST /api/generate`, `qwen2.5-coder:1.5b-base`, `fim: true`, промпт 1292 симв. |
| **Индексация кодовой базы** | ✅ | `POST /api/embed`, `nomic-embed-text:latest` |
| **Чат в IDE** (плагин ProxyAI) | ✅ | `POST /api/chat`, `qwen3-coder:30b`, реальный вопрос про `ChatViewModel`, ответ на русском |
| **Чат** (Continue CLI, запасной путь) | ✅ | `POST /v1/chat/completions`, `qwen3-coder:30b`, ответ по существу |
| **Чат-панель самого Continue в Android Studio** | ❌ | JCEF, см. ниже. Не чинится подменой runtime |
| **Inline Edit Continue (`Cmd+I`)** | ⚠️ | висит, если в сессии открывалась чат-панель Continue: её падение убивает шину сообщений плагина. Чат вынесен в ProxyAI, проблема обойдена |

## Что ушло в модель на автокомплите

```json
{
  "model": "qwen2.5-coder:1.5b-base",
  "fim": true,
  "prompt_chars": 1292,
  "options": {
    "temperature": 0.05, "top_p": 0.9, "num_predict": 128, "num_ctx": 4096,
    "stop": ["\n\n", "<|endoftext|>", "<|fim_prefix|>", "<|fim_middle|>", "<|fim_suffix|>", "..."]
  }
}
```

Все параметры - мои из `config.yaml`, включая стоп на пустой строке.

## Находка: без стопа автокомплит не показывался вовсе

Первая живая попытка: запрос уходил, а подсказка не появлялась. Повторили тот же запрос напрямую:

| Настройка | Задержка | Токенов | Что вернула модель |
|---|---:|---:|---|
| `num_predict: 128`, без стопа | 900 мс | 128, упор в лимит | верное начало, дальше переписала полфайла |
| **`stop: ["\n\n"]`** | **171 мс** | 20, штатный стоп | `filter { message -> message.isFavorite }.map { ... }` |
| `stop: ["\n"]` | 107 мс | 10 | только одна строка |

Модель отвечала правильно с самого начала. Плагин выбрасывал подсказку целиком, потому что её хвост
дублировал код, который уже есть ниже по файлу. Один параметр - и подсказка появилась, а задержка
упала впятеро. Это ровно тот случай, когда «локальная модель не работает» на деле означает
«обвязка не настроена».

## Почему чат-панель Continue не работает в Android Studio 2026.1

Стек падения из `idea.log`:

```
java.lang.NoSuchMethodError: 'boolean com.jetbrains.cef.JCefAppConfig.isRemoteEnabled()'
  at ContinueBrowser.<init>(ContinueBrowser.kt:19)
  at CoreMessenger.handleMessage(CoreMessenger.kt:61)
```

Что выяснено проверкой, а не догадкой:

| Runtime | JCEF | Метод `isRemoteEnabled` |
|---|---|---|
| Встроенный в Android Studio 2026.1 (`21.0.10+-117844308-b1163.108`) | **нет вообще** - ни модуля, ни фреймворка | - |
| `jbr_jcef-21.0.10+7-b1163.108` | есть | **нет** (проверено `javap`) |
| `jbr_jcef-21.0.11+10-b1163.116` | есть | **нет** |
| `jbr_jcef-25.0.3+9-b508.16` | есть | **нет** |

Google в этой сборке Android Studio поставляет JBR без JCEF, а платформа зовёт метод, которого нет
ни в одной стоковой сборке JetBrains Runtime. Подменой boot runtime это не лечится - три сборки
проверены и отброшены.

Хуже того: падение инициализации чат-панели рвёт `CoreMessenger` - шину между плагином и его ядром.
Поэтому после открытия панели перестаёт отвечать и Inline Edit. Пока панель не трогать - автокомплит
и Edit живут.

## Что делать с чатом в IDE - решено

Взят **ProxyAI 3.8.2-261** - плагин JetBrains с нативным Swing-UI, JCEF ему не нужен, совместим
с платформой 261. Настроен на Ollama, роль Chat -> `qwen3-coder:30b`. Проверено живьём: вопрос
пользователя ушёл в модель (`POST /api/chat`), ответ вернулся в панель.

Две настройки, без которых он не работает как надо:

1. **Служебную папку плагина спрятать.** ProxyAI в агентном режиме создаёт `.proxyai/checkpoints/`
   и сам же пытается её прочитать как файл -> `IOException: getInputStream() must not be called
   against a directory`. Папка добавлена в `.gitignore` и `.continueignore`.
2. **Язык и конвенции - в персону ProxyAI.** Он не читает `.continue/rules/`, поэтому файл правил
   Дня 1 продублирован в System Prompt / Persona плагина: «отвечай на русском, код на английском»
   плюс ключевые конвенции. Без этого модель отвечает по дефолтному английскому промпту плагина.

Запасной путь, если плагин отвалится: **Continue CLI** (`npx @continuedev/cli --config ~/.continue/config.yaml`) -
тот же конфиг, тот же ollama, чат и агент в терминале. Проверено, `POST /v1/chat/completions`.

**Автокомплит оставлен за Continue.** У ProxyAI code completion не включаем - два плагина будут драться
за одну подсказку. Continue настроен под 1.5B-base и отвечает за 200 мс, ProxyAI - только чат.

## Побочно: чужая настройка, которая мешала

В `~/Library/Application Support/Google/AndroidStudio2026.1.2/studio.jdk` лежал путь к
`jbr_jcef-21.0.10`, **а в конце файла стоял лишний пробел** - лаунчер такой путь не резолвит и молча
падал на встроенный runtime. Файл убран в `studio.jdk.jcef-broken`, студия работает на встроенном
runtime. Если он был нужен для чего-то ещё - вернуть переименованием.
