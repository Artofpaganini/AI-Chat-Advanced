Задание: оценка уверенности и контроль качества инференса.
Ниже — построчно: что требовалось, где это лежит, какие цифры получились.

Все числа берутся из артефактов в `results/` и `raw/`, не из прозы. Метрики пересчитаны независимо
при ревью и сошлись.

## 1. Задача, где ошибка недопустима

| | |
|---|---|
| **Что выбрано** | Триаж сообщения родителя -> выбор действия |
| **Где описано** | `SPEC.md`, раздел 1 |
| **Тип задачи** | Классификация плюс выбор действия, четыре класса |
| **Классы** | `EMERGENCY` / `DOCTOR_SOON` / `SELF_CARE` / `OFF_TOPIC` |
| **Почему ошибка недопустима** | Пропуск экстренного случая — ребёнок не попал к врачу. Цена ошибки несимметрична, поэтому при сомнении маршрут поднимается вверх |

**Без fine-tuning:** всё построено вокруг готовой модели, дообучение в основной части не применяется.
Отдельный эксперимент с дообучением есть в конце этого документа и помечен как работа **сверх
задания** — он не подменяет требование, а проверяет его границу.

## 2. Механизмы оценки уверенности

Требовалось минимум 2. Сделано 4.

| Подход | Где код | Что делает | Что доказывает работу |
|---|---|---|---|
| **Constraint-based** | `harness/guards.py` | 14 проверок: формат JSON, допустимые значения, логические инварианты, плюс предусловия входа | `REPORT.md` разд. 3, строка «нарушения ограничений» |
| **Redundancy** | `harness/pipeline.py`, функция `run_pipeline` | Один запрос выполняется 3 раза при t=0.7, ответы сравниваются голосованием | `REPORT.md` разд. 4В, таблицы голосов |
| **Self-check** | `harness/pipeline.py`, критик | Модель проверяет собственный результат, возвращает вердикт и признак упущенного риска | `REPORT.md` разд. 4Г и 4Е |
| **Scoring** | `harness/pipeline.py`, функция скоринга | Возвращает `confidence` и статус `OK` / `UNSURE` / `FAIL` | `results/smoke_report.json`, сценарий 5 |

### Детали по каждому

**Constraint-based** — `SPEC.md` разделы 3 и 3.1. Коды проверок:
- формат: `C_JSON`, `C_KEYS`, `C_TYPES`
- допустимые значения: `C_ROUTE_ENUM`, `C_CONF_RANGE`, `C_AGE_RANGE`, `C_FLAGS_SHAPE`, `C_REASON_LEN`
- логические инварианты: `C_INV_EMERGENCY_FLAGS`, `C_INV_SELFCARE_FLAGS`, `C_INV_OFFTOPIC_CLEAN`, `C_INV_CONF_FLOOR`
- предусловия входа: `C_IN_EMPTY`, `C_IN_NO_LETTERS`

**Redundancy** — `SPEC.md` раздел 4. Голосование идёт **не по большинству, а по максимуму тяжести**:
одного голоса за `EMERGENCY` достаточно, чтобы поднять маршрут. Обоснование там же.

**Self-check** — `SPEC.md` раздел 5. Триггер настраивается: по разбросу голосов, по признаку риска в
тексте, либо всегда. Сравнение трёх режимов — `REPORT.md` разд. 4Г.

**Scoring** — `SPEC.md` раздел 6. Формула и пороги 0.75 / 0.40 заданы **до первого замера**.

## 5. Результат: инференс с явной оценкой уверенности

**Что на выходе.** Каждое решение несёт маршрут, `confidence` от 0 до 1 и статус:

| Статус | Условие | Что делает приложение |
|---|---|---|
| `OK` | уверенность >= 0.75, нет неустранённых нарушений | Показывает ответ как есть |
| `UNSURE` | 0.40 .. 0.75, либо сработал подъём по безопасности | Показывает с пометкой и советом проверить у врача |
| `FAIL` | ниже 0.40, либо не осталось валидных голосов, либо негодный вход | Ответ не показывается, отдаётся безопасная заглушка |

**Доказательство, что механизмы реально работают:** `harness/smoke.py`, одна команда, живой прогон.
Результат — 5 из 5, отчёт в `results/smoke_report.json`. Гейт возвращает код 1 при провале.

| Сценарий смоука | Что доказано |
|---|---|
| Предусловие входа | Пустая строка -> `FAIL`, 0 вызовов, 0 денег |
| Constraint на выходе | Коды проверены, ремонт отработал |
| Redundancy | Три голоса собраны, итог равен максимуму по тяжести |
| Self-check | Критику подсунули заниженный маршрут на очевидно экстренном случае -> развернул решение |
| Scoring | `confidence` разложена на три слагаемых, сумма сошлась, статус выведен по порогам |

## 6. Что показал замер, кроме требуемых цифр

Это не требовалось заданием, но без этого выводы были бы приукрашены.

| Находка | Где | Суть |
|---|---|---|
| А | `REPORT.md` 4А | Пустой вход давал `EMERGENCY` с уверенностью 0.822. Повторы бессильны: модель галлюцинирует уверенно и одинаково. Лечится проверкой входа, а она бесплатна |
| Б | 4Б | На сильной модели контроль не поднимает точность. Его польза — пометить шаткие решения, а не улучшить их |
| В | 4В | **Контроль не уменьшил число пропущенных экстренных случаев ни на одной модели**: 0->0, 3->3, 4->4. Повторы ловят неустойчивость, а не незнание |
| Г | 4Г | Триггер критика по разбросу голосов не срабатывает там, где нужен. Но «звать всегда» даёт треть ложных тревог |
| Д | 4Д | Одиночный прогон не является измерением: разброс точности 8.7 пункта между одинаковыми прогонами. **Два вывода в отчёте пришлось исправить** |
| Е | 4Е | Самопроверка той же моделью не даёт независимого сигнала. Чужой критик снижает ложные тревоги с 13 до 3 устойчиво |

## 7. Сверх задания: проверка границы через дообучение

Задание требует решения **без fine-tuning**, и основная часть ему соответствует. Но находка В
показала предел подхода: контроль не лечит незнание модели. Проверили это прямо — вылечили незнание
данными.

Где: `REPORT.md` раздел 4Ж. Обучающий набор `data/train_triage.jsonl`, 260 примеров, написан отдельно
и не пересекается с тестом (максимальный Жаккар 0.382 при пороге 0.6, точных совпадений ноль).

| Вариант | accuracy | пропущено EMERGENCY | p50 |
|---|---|---|---|
| Qwen база | 0.6087 | 4 | 1628 мс |
| Qwen база + контроль | 0.6087 | 4 | 9298 мс |
| Qwen дообучена | 0.8261 | 1 | 1423 мс |
| Qwen дообучена + контроль | 0.7609 | **0**, устойчиво в 3 прогонах | 10674 мс |

Вывод: контроль и данные лечат разное. Контроль не двигал ни точность, ни пропуски — дообучение
сдвинуло оба. Вместе они впервые дали ноль пропусков воспроизводимо.

Отдельно: чекпоинт с **худшей** валидационной ошибкой показал **лучшее** поведение. Выбор по минимуму
val loss дал бы 0.6522 вместо 0.8261.

**Проверка на запоминание пройдена.** Низкий train loss сам по себе зубрёжку не доказывает. Прямая
проверка — подменить числа во входе и посмотреть, следует ли ответ за ними:

| Вход | Ответ | Возраст распознан |
|---|---|---|
| Сыну 2 месяца, температура 38.2 | `EMERGENCY` | 2 |
| Сыну 3 года, температура 38.2 | `DOCTOR_SOON` | 36 |
| Дочке 5 недель, рвёт фонтаном | `EMERGENCY` | 1 |
| Дочке 4 года, вырвало один раз | `SELF_CARE` | 48 |

Один и тот же симптом при разном возрасте даёт разный маршрут. Модель читает вход, а не
воспроизводит заученное. Низкие потери объясняются узостью задачи: четыре класса и жёсткий формат
выучиваются почти идеально, и это не мешает обобщению.

**Где настоящий предел.** Обучение до 500 итераций дало 0.7174 против 0.8261 на 300 — вот это уже
переобучение, и видно его только по поведению, не по кривой потерь.

## 8. Как проверить самому

```bash
cd challenge_advanced/task7

# план вызовов и оценка стоимости, без обращения к сети
python3 harness/run_eval.py --dry-run --mode both

# полный прогон обоих режимов
python3 harness/run_eval.py --mode both --workers 6

# метрики и сравнение baseline против pipeline
python3 harness/report.py

# смоук: доказательство, что каждый механизм срабатывает
python3 harness/smoke.py
```
