# Каталог сценариев — даёшь мне, я выполняю вживую

Формат придуман так, чтобы ты **правил что угодно** (текст, порядок, ожидания, таргет), а я исполнял через
реальный MCP-драйвер и честно докладывал результат — включая падения. Это не скрипт-заготовка: каждый шаг
транслируется в конкретный MCP-вызов в момент прогона.

## Как дать сценарий

Просто вставь блок в чат. Минимум — название, таргет и шаги:

```
СЦЕНАРИЙ: Отправка двух сообщений подряд
ТАРГЕТ: android
ШАГИ:
  1. запусти приложение
  2. введи "Сколько будет 2+2?"
  3. тапни "Send"
  4. жди появления ответа
  5. проверь что видно "4"
  6. скриншот two_msg
```

Можно короче — прозой («запусти, напиши привет, проверь что ответ пришёл»). Я разложу на шаги сам и покажу,
во что разложил, до исполнения.

## Словарь действий (что я реально умею)

| Шаг | MCP-вызов под капотом | Примечание |
|---|---|---|
| `запусти приложение` | `app:launch` | холодный старт |
| `перезапусти приложение` | `app:stop` + `app:launch` | force-stop, данные НЕ трутся |
| `переустанови сборку` | `app:install` | ставит поверх (`-r`) |
| `введи "<текст>"` | `input:text` | сначала автоматически тапаю поле ввода |
| `тапни "<текст>"` | `input:tap text:` | по тексту — устойчиво к сдвигу от клавиатуры |
| `тапни иконку ★ / ↑ / ↓ / 🎤` | `input:tap x,y` | ★=фильтр избранного, ↑=export, ↓=import |
| `тапни звезду на сообщении N` | `input:tap x,y` | координаты беру из свежего скриншота |
| `свайп вверх / вниз` | `input:swipe` | прокрутка списка |
| `нажми <BACK\|HOME\|ENTER>` | `input:key` | |
| `жди <N> сек` / `жди появления "<текст>"` | `system:wait` / `ui:wait` | |
| `проверь что видно "<текст>"` | `ui:assert_visible` / `ui:tree` | падение = FAIL сценария |
| `проверь что НЕ видно "<текст>"` | `ui:assert_gone` | |
| `скриншот <имя>` | `screen:capture` + сохранение PNG | попадёт в отчёт |
| `дамп UI` | `ui:tree format:semantic` | текстовое дерево, дешевле скриншота |
| `проверь файл на устройстве <путь>` | `adb run-as ls -l` | доказательство, а не тост |
| `проверь логи на краши` | `adb logcat` grep FATAL | |
| `открой <url>` | `system:open_url` | |

**Таргеты:** `android` (эмулятор Small_Phone) · `ios` (симулятор, нужен запуск) · `web` (dev-сервер `localhost:8080`,
драйв через browser-модуль MCP) · `desktop`.

## Что я НЕ умею (чтобы не гадал)

- Скриншот прямо в файл средствами MCP — MCP отдаёт картинку мне, файл сохраняю через `adb`. На результат не влияет, но знай.
- `system:shell` с пайпами (`|`) — блокируется как shell-injection; такие команды гоню через Bash.
- Ввод капчи, платежи, реальные учётки — не делаю (в этом приложении и не нужно).
- Физическое iOS-устройство — не поддерживается драйвером, только симулятор.

## Банк кубиков — из них собирай свои

Негативные / краевые, которые в базовом наборе НЕ покрыты (хорошие кандидаты, чтобы меня погонять):

- отправка **пустого** сообщения → Send должен остаться неактивен;
- очень **длинный** текст (500+ символов) → проверить перенос и отсутствие обрезки;
- **кириллица / эмодзи / спецсимволы** в сообщении → проверить корректный рендер и ответ;
- отправка **без сети** (`adb shell svc data disable` / airplane mode) → проверить обработку ошибки без краша;
- **несколько сообщений подряд** без ожидания ответа → проверить порядок баблов;
- фильтр ★ при **нулевом** количестве избранного → проверить empty-state;
- **двойной import** подряд → проверить дубликаты по id (тут есть известная находка про MERGE и favorite);
- **поворот экрана** (`adb shell settings put system user_rotation 1`) → проверить сохранение состояния;
- **свайп** длинной истории вверх/вниз → проверить, что старые сообщения на месте;
- 🎤 **STT**: тап по микрофону → проверить, что запрашивается разрешение / нет краша.

## Как проверить, что я исполняю, а не пересказываю

- **Меняй данные.** Впиши свой текст сообщения — я введу именно его, и в отчёте будет реальный ответ модели, который заранее знать нельзя.
- **Меняй порядок и ожидания.** Поставь заведомо ложную проверку (`проверь что видно "Абракадабра"`) — я обязан вернуть **FAIL** с диагнозом, а не подогнать результат.
- **Проси дамп UI** в произвольный момент — это живое дерево экрана.
- **Требуй артефакт.** «проверь файл на устройстве» / «проверь логи» — там реальные размеры, таймстампы, PID.

Если сценарий упадёт — я не чиню молча: пишу шаг, что ожидалось, что увидел, и где предполагаю причину
(модуль/функция), после чего спрашиваю, чинить или это ожидаемое поведение.
