# Промпты для двух уровней тестирования

Готовые промпты, которые выдаются ассистенту. Оба описаны применительно к текущему приложению
**AI-Chat-Advanced** (Jarvis - KMM + Compose Multiplatform чат с DeepSeek).

Приложение без авторизации и без «удаления» как отдельной операции. Классический CRUD-шаблон
(`логин -> создать сущность -> проверить что появилась -> удалить`) отображён на реальные операции приложения:

| CRUD-шаблон | Операция в приложении |
|---|---|
| логин | *нет* (приложение без auth) -> «холодный старт до готового экрана» |
| создать сущность | отправить сообщение -> появляется пара «user-бабл + ответ AI» |
| проверить что появилась | бабл отрисован в списке / пережил рестарт процесса |
| обновить | пометить сообщение избранным (☆->★) |
| удалить (из выборки) | снять избранное / фильтр ★ убирает не-избранные из видимой выборки |

---

## Уровень 1 - промпт на автотесты кода

> **Роль:** ты пишешь unit/integration тесты на бизнес-логику этого KMM-проекта.
>
> **Задача:**
> 1. Пройди по модулям `feature/chat`, `feature/ai`, `core/viewmodel` и найди **непокрытый** код
>    бизнес-логики: мапперы (`data`/`presentation`), репозитории, use-cases, датасорсы. UI-Composable и
>    платформенные `actual` не покрываем.
> 2. Для каждого непокрытого класса напиши тесты в `src/commonTest` соответствующего модуля.
>    Инфраструктура: `kotlin.test` + `kotlinx-coroutines-test` (`runTest`) + `turbine` для Flow.
>    Для KMM-модуля с Android-таргетом убедись, что в `build.gradle.kts` включён `withHostTest {}` -
>    иначе тесты уйдут только на iOS-симулятор.
> 3. Придерживайся конвенций репозитория: модели `*RequestModel`/`*ResponseModel`/`*DataModel`/`*Model`/`*UiModel`;
>    никаких `*UiState`-классов и слова «DTO»; мапперы - top-level extension-функции; `internal` по умолчанию;
>    именованные параметры лямбд (без `it`). Fake-датасорсы вместо моков файловой системы/сети.
> 4. Покрой все ветки: success / success-empty / server-error / client-error, а для импорта - обе стратегии
>    (REPLACE и MERGE), включая конфликт по `id`.
> 5. **Запусти** `./gradlew :feature:chat:testAndroidHostTest :feature:ai:testAndroidHostTest` и **убедись,
>    что всё зелёное с первого прогона**. Красный тест - почини тест или зафиксируй продовую находку отдельно.
> 6. Отчёт: список файлов, число тестов, вывод прогона (passed), найденные продовые дефекты (если есть).
>
> **Минимум:** 3 файла тестов. **Критерий готовности:** `BUILD SUCCESSFUL`, 0 failed, отчёт приложен.

**Факт исполнения:** 5 файлов, 30 тестов, зелёные с первого прогона (см. `README.md` -> Level 1).
Найдены 2 продовые находки (тестируемость `ChatViewModel`, MERGE-сброс favorite).

## Уровень 2 - промпт на smoke через MCP (пользовательские сценарии)

> **Роль:** ты сам протыкиваешь UI приложения через MCP-драйвер (веб -> Playwright по
> `http://localhost:8080`; мобилка -> claude-in-mobile по эмулятору) и фиксируешь результат.
>
> **Общие правила для каждого сценария:** делай скриншот на каждом шаге; после действия проверяй ожидаемый
> результат по факту на экране (не по предположению); в конце - вердикт `PASS/FAIL`; при `FAIL` укажи шаг и
> предполагаемое место проблемы (модуль/функция).

### Сценарий 1 - Холодный старт (аналог «логина»)
1. Установи/открой приложение (mobile: reinstall+launch; web: открой `localhost:8080`).
2. Дождись готового экрана.
- **Ожидание:** отрисованы шапка «Jarvis», поле ввода, кнопка Send, empty-state; краша нет.

### Сценарий 2 - Отправить сообщение (create -> проверить что появилось)
1. В поле ввода набери `Privet`.
2. Нажми Send.
3. Дождись ответа.
- **Ожидание:** появился user-бабл `Privet`; ниже - **реальный ответ DeepSeek**; иконка 🔊 (TTS) на ответе.

### Сценарий 3 - Избранное + фильтр (update -> «убрать из выборки»)
1. Тапни ☆ на бабле -> должна стать ★.
2. Включи фильтр ★.
3. Проверь выборку. Выключи фильтр.
- **Ожидание:** при фильтре ★ видно только избранное (не-избранные скрыты); toggle обратим (★->☆).

### Сценарий 4 - Export / Import JSON
1. Нажми Export -> проверь снэкбар с путём файла.
2. Нажми Import (мок `mock_chat_history.json`) -> проверь, что сообщения из мока появились.
- **Ожидание:** экспорт-файл создан на диске; после импорта список содержит сообщения из мока.

### Сценарий 5 - Persistence (проверить, что данные пережили рестарт)
1. Убей процесс (mobile: `force-stop`; web: hard-reload вкладки).
2. Открой приложение заново.
- **Ожидание:** вся история (отправленное сообщение + ответ + импортированный мок) на месте - данные не in-memory.

> **Отчёт:** таблица `сценарий -> вердикт -> скриншоты -> что проверено`; итог `N/N PASS`; на `FAIL` - диагноз.

**Факт исполнения (mobile/adb):** 5/5 PASS, 10 скринов (см. `smoke/report.md`).
**Факт исполнения (web/MCP):** см. `smoke/web/report.md` (после сборки web-таргета).
