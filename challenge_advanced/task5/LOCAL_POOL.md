# Пул C - 10 простых задач для локальной модели

Модель: `qwen3-coder:30b` на Ollama (локально, без сети).
Харнесс: переиспользован от task4 - `challenge_advanced/task4/harness/agent_loop.py`.
Инструменты у модели: `list_dir`, `search`, `read_file`, `write_file`, `build`.

## Условия прогона

| | |
|---|---|
| Песочница | клон репозитория, реальный проект не трогается |
| Гейт | компиляция `:feature:chat:compileCommonMainKotlinMetadata`, offline |
| Лимиты на задачу | 50 шагов, 40 минут |
| Провал задачи | сборка красная после лимита, либо модель не вызвала ни одного инструмента |
| Между задачами | при провале песочница откатывается, чтобы мусор не тянулся дальше |

Задачи специально простые - размер XS-S, почти все в один-два файла. Смысл замера не в том,
чтобы локальная модель сделала сложное, а в том, чтобы понять, **сколько простых задач подряд она
вытянет** и где сломается.

## Задачи

| # | Задача | Файлы | Критерий DONE |
|---|---|---|---|
| 1 | **Счётчик символов** под полем ввода | `MessageInputBar.kt` | под полем видно текущую длину текста, компиляция зелёная |
| 2 | **Лимит длины сообщения** | `MessageInputBar.kt` или маппер | есть константа максимума, при превышении отправка блокируется |
| 3 | **Крестик очистки поля ввода** | `MessageInputBar.kt` | когда в поле есть текст, справа виден крестик, тап очищает поле |
| 4 | **Число сообщений в заголовке** | `ChatScreen.kt` / топбар | в заголовке рядом с «Jarvis» видно количество сообщений |
| 5 | **Плейсхолдер во время генерации** | `MessageInputBar.kt` | пока идёт ответ, подсказка в поле меняется на другой текст |
| 6 | **Дизейбл экспорта и очистки на пустой истории** | `ChatTopBarActions.kt` | при пустом чате кнопки экспорта и очистки неактивны |
| 7 | **Кнопка «наверх» в топбаре** | `ChatTopBarActions.kt` + `ChatScreen.kt` | тап скроллит список к самому первому сообщению |
| 8 | **Ограничить высоту поля ввода** | `MessageInputBar.kt` | поле растёт максимум до нескольких строк, дальше скроллится внутри |
| 9 | **Счётчик избранных у иконки фильтра** | `ChatTopBarActions.kt` | рядом с иконкой избранного видно их количество |
| 10 | **Две новые подсказки в пустом состоянии** | `ChatEmptyState.kt` | в списке подсказок стало на две больше |

## Метрики - заполняется прогоном

Заполняется автоматически скриптом `local_pool_run.py`, ничего руками не подгоняется.

| # | Задача | Итог | Шагов | Вызовов инструментов | Сборок | Токенов | Время (мин) |
|---|---|---|---|---|---|---|---|
| 1 | Счётчик символов | OK | 27 | 23 | 8 | 4190 | 6.0 |
| 2 | Лимит длины сообщения | OK | 32 | 28 | 4 | 5211 | 6.5 |
| 3 | Крестик очистки поля ввода | OK | 38 | 34 | 9 | 8903 | 12.6 |

Прогон прерывался на 4-й задаче (фоновый процесс убит) и был доведён доводом с 4-й - задачи 1-3
сохранены коммитами в песочнице, переделывать их не пришлось.

### Наблюдения по ходу

- **Модель не читает ошибку компилятора, а перегенерирует файл целиком.** На первой задаче: четыре
  красных сборки подряд, каждый раз файл переписывался с нуля вместо точечной правки.
- **Модель не понимает, что задача закончена.** Зелёная сборка получена на 14-м шаге, но работа
  продолжалась до 27-го - протокол завершения в харнессе есть, модель им не пользуется.
  Следствие: время на задачу упирается в лимит шагов, а не в реальную сложность.
- **Стоимость на задачу растёт с числом файлов.** Задача 3 (крестик в поле ввода) потребовала вдвое
  больше токенов и времени, чем задача 1, хотя обе - одна и та же зона одного файла.
