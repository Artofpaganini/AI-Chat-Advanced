# Task10 - micro-model first, проверка перед LLM

Двухуровневый инференс. Внизу дешёвый классификатор на TF-IDF и логистической регрессии, он считается
локально за доли миллисекунды и стоит ноль. Наверху `deepseek-v4-flash`, он стоит деньги и время.
Дешёвый уровень отвечает сам, когда уверен, и зовёт большую модель, когда нет.

Задача та же, что в task7, task8 и task9 - триаж сообщения родителя в приложении ALVA. Свободный
текст -> `EMERGENCY` / `DOCTOR_SOON` / `SELF_CARE` / `OFF_TOPIC`.

## Требования

- Python 3.9, **только стандартная библиотека**. Ни numpy, ни sklearn не нужны и не используются.
- Ключ `DEEPSEEK_API_KEY` - в окружении либо в `local.properties` в корне репозитория.
  В артефакты и логи он не попадает.
- Сеть нужна только режимам `only_llm` и `cascade`. Обучение и `only_micro` работают без неё.

## Команды

Всё запускается из каталога задачи.

```bash
cd challenge_advanced/task10

# 1. обучить micro-model и записать веса (сеть не нужна, около 3 минут)
python3 harness/train_micro.py

# 2. посмотреть план прогона: сколько будет вызовов и сколько это стоит, без единого запроса
python3 harness/run_pipeline.py --dry-run --mode all

# 3. прогнать три режима по три повтора
python3 harness/run_pipeline.py --mode all --repeats 3 --workers 3

# 4. пересчитать метрики из raw/ и проверить гейт
python3 harness/report10.py
```

Отдельные полезные вызовы:

```bash
# только файл паритета, без сети и без прогонов
python3 harness/run_pipeline.py --parity-only

# только micro-model, вообще без сети
python3 harness/run_pipeline.py --mode only_micro --repeats 3

# обучение без строк, пересекающихся с оценочным набором
python3 harness/train_micro.py --exclude-eval-overlap
```

`report10.py` возвращает код 1, если гейт из `SPEC.md` раздел 10 не пройден. Это удобно вешать в CI.

## Что где лежит

```
harness/
  spec10.py         константы: пути, метки, гиперпараметры, сетка порогов, условия гейта
  micro_model.py    инференс: нормализация, признаки, вектор, softmax, решение об эскалации
  train_micro.py    обучение, проверка утечки, обрезка словаря, подбор порогов, экспорт весов
  run_pipeline.py   три режима, три повтора, --dry-run, запись сырья
  report10.py       пересчёт метрик из raw/, гейт, код возврата 1 при провале

results/
  micro_model.json      веса по контракту WEIGHTS_FORMAT.md
  parity_python.json    эталон для Kotlin-теста паритета
  pipeline_report.json  все числа отчёта
  train_report.json     что было при обучении: утечка, пороги, размеры словаря

raw/
  pipeline_<режим>.jsonl        первый повтор
  pipeline_<режим>_r2.jsonl     второй
  pipeline_<режим>_r3.jsonl     третий
```

Данные не дублируются: обучающий корпус и оценочные кейсы берутся из `../task7/data/`.

## Четыре режима

| Режим | Что делает | Зачем |
|---|---|---|
| `only_llm` | всё уходит в большую модель | верхняя граница по качеству и цене |
| `only_micro` | только micro-model, эскалации нет | нижняя граница, показывает цену отказа от LLM |
| `cascade` | micro-model, эскалация по `UNSURE`, вердикт LLM побеждает | первая редакция контракта |
| `cascade_max` | то же, но итог - более тяжёлый из двух вердиктов | раздел 5.1 контракта, исправленное правило |

Каждый прогоняется три раза, потому что облачная модель на одном и том же входе даёт разные ответы.
Это доказано замером в task8, поэтому решение принимается по худшему прогону.

`cascade_max` добавлен после первого замера, который вскрыл дефект в правиле слияния. Правило
менялось уже после того, как числа были увидены - это записано в `SPEC.md` раздел 11 и в `REPORT.md`
раздел 8, и его качество на том же наборе кейсов доказательством не считается.

Гейт `report10.py` считается по режиму `cascade` и он же решает код возврата. Для `cascade_max` те же
пять пунктов печатаются справочно.

## Паритет Python и Kotlin

`results/parity_python.json` - эталон. На каждый из 50 кейсов там лежит метка, вероятность, margin,
статус и полный вектор вероятностей. Kotlin-тест читает тот же `cases.jsonl` и тот же
`micro_model.json`, считает то же самое и сверяет с допуском `1e-6`.

Тест обязан падать, если разошёлся хоть один кейс. Без пройденного паритета задача не считается
сделанной.
