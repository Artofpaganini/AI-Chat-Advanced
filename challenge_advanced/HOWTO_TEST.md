# Как проверить задачи 7 и 8

Пошагово, от простого к сложному. Каждый шаг заканчивается тем, что вы видите своими глазами.

Всё запускается системным Python, ставить ничего не нужно. Отдельное окружение требуется только для
локальной модели - это шаг 4 и дальше.

## Шаг 4. Проверить, что механизмы реально работают (3 минуты, копейки)

Это самая наглядная проверка: каждый из механизмов показывается в действии.

```bash
python3 harness/smoke.py
```

Пять сценариев подряд:
1. Пустая строка -> отказ, ноль обращений к модели
2. Проверка формата ответа
3. Три голоса и подъём маршрута по максимуму тяжести
4. Критику подсовывают заниженный маршрут на очевидно экстренном случае - он разворачивает решение
5. Разбор уверенности на три слагаемых, сумма сходится с итогом

Ожидаемо: `ИТОГ: пройдено 5 из 5`. Код возврата 0. Если хоть один сценарий упадёт - код 1.

## Шаг 5. Поднять локальную модель (нужно один раз, 10 минут)

Дальше идут проверки, где участвует дообученная модель. Ей нужен сервер.

```bash
# окружение, ставится один раз
uv venv ~/mlxenv --python 3.11
uv pip install --python ~/mlxenv/bin/python mlx-lm

# запуск сервера, оставить работать в отдельном окне
```

Первый запуск скачает модель, около 1 ГБ.

Проверка, что живой:
```bash

```
Должен вернуть JSON со списком моделей.

Адаптер дообучения лежит в `~/models/alva-triage-qwen-lora`. Он **не передаётся** флагом при запуске
сервера - тот молча его игнорирует. Адаптер уходит полем `adapters` в теле каждого запроса, это уже
зашито в харнесс.

## Шаг 6. Убедиться, что дообучение дало эффект (5 минут, бесплатно)

```bash
cd challenge_advanced/task7

# базовая модель, без дообучения
python3 harness/run_eval.py --mode baseline \
  --base-url http://127.0.0.1:8081/v1 \
  --model mlx-community/Qwen3-1.7B-4bit \
  --out-suffix _check_base --workers 2

# та же модель с адаптером
python3 harness/run_eval.py --mode baseline \
  --base-url http://127.0.0.1:8081/v1 \
  --model mlx-community/Qwen3-1.7B-4bit \
  --adapters ~/models/alva-triage-qwen-lora \
  --out-suffix _check_tuned --workers 2
```

Сравнить:
```bash
python3 harness/report.py \
  --baseline raw/baseline_runs_check_base.jsonl \
  --pipeline raw/baseline_runs_check_tuned.jsonl \
  --out results/check_tuning.json
```

Ожидаемо: точность вырастет примерно с 0.61 до 0.83, пропущенные экстренные случаи упадут с 4 до 1.

## Шаг 7. Проверить роутинг task8 (10 минут, около 1 цента)

Нужен работающий сервер из шага 5.

```bash
cd ../task8

# нижняя точка отсчёта: всё на дешёвой модели, бесплатно
python3 harness/run_router.py --strategy only_cheap --workers 3

# верхняя точка: всё на облачной
python3 harness/run_router.py --strategy only_strong --workers 3

# сам роутер
python3 harness/run_router.py --strategy route_all --workers 3

# сводка
python3 harness/router_report.py raw
```

На что смотреть:
- `route_all` должен дать точность на уровне `only_strong`, но дешевле примерно на четверть
- колонка `low`/`high` - сколько вызовов ушло на дешёвый и сильный уровень
- блок «польза эскалации» - сколько подъёмов наверх реально изменили ответ. Большая часть окажется
  впустую, это ожидаемый результат, а не поломка

## Шаг 8. Увидеть недетерминизм своими глазами (2 минуты)

Самая интересная проверка. Один и тот же запрос к облачной модели при температуре 0 может дать разные
ответы.

```bash
cd ../task8
for i in 1 2 3; do
  mkdir -p raw/check$i
  python3 harness/run_router.py --strategy only_strong --out-dir raw/check$i --workers 3 > /dev/null 2>&1
done

python3 -c "
import json,os
cases={r['id']:r for r in (json.loads(l) for l in open('../task7/data/cases.jsonl'))}
for d in ('raw/check1','raw/check2','raw/check3'):
    rows=[json.loads(l) for l in open(os.path.join(d,'router_only_strong.jsonl'))]
    g=[r for r in rows if cases[r['case_id']]['expected_route']]
    corr=sum(1 for r in g if r.get('final_route')==cases[r['case_id']]['expected_route'])
    print('%s точность %.4f'%(d,corr/len(g)))
"
```

Три прогона одного и того же кода на одних и тех же данных. Цифры могут совпасть, а могут разойтись -
и это главный аргумент в пользу того, что одиночный замер ничего не доказывает.

## Что делать, если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `ключ не найден` | Нет ключа DeepSeek | Проверить `local.properties` в корне репозитория или задать `DEEPSEEK_API_KEY` |
| Прогон с локальной моделью падает по таймауту | Сервер не поднят | Шаг 5, проверить `curl http://127.0.0.1:8081/v1/models` |
| Дообученная модель отвечает как базовая | Адаптер не применился | Убедиться, что в команде есть `--adapters`, флаг при запуске сервера не работает |
| Цифры не совпадают с отчётом | Так и должно быть | Разброс между одинаковыми прогонами до 8 пунктов, см. `task7/REPORT.md` разд. 4Д |
| `router_report` возвращает код 1 | Сработал гейт безопасности | Это не ошибка запуска, а результат: какая-то стратегия теряет экстренные случаи |
