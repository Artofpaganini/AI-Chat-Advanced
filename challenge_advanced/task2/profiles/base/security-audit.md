# Профиль: Security-Audit — base

> Base-тюнинг универсального flow. **Контекст base — кросс-платформа (Android/KMM/Backend), generic-агенты; если проект окажется реальным xbet/alva — переключиться на их roster.**
> Стек/сабагенты — `base/roster.md`; общее — секции «Оркестрация»/«Стадии»/«Профили» глобального `~/.claude/CLAUDE.md` + `./conventions.md` (не дублировать).
> **Направление стека (Android / KMM+CMP / Backend) выбирается на создании задачи** (backend добавляет server-side-линзы: SQLi, authZ на эндпоинтах, secrets в env/конфиге).

## Назначение / когда активен
**READ-ONLY аудит безопасности** — секреты, авторизация, зависимости/CVE, лицензии, OWASP-паттерны. Только отчёт + рекомендации.
Триггеры: «проверь на уязвимости», «security-аудит», «нет ли утёкших секретов», «проверь зависимости/лицензии/CVE», «безопасна ли авторизация».
Примеры: «нет ли захардкоженных ключей», «аудит auth-потока», «проверь deps на известные CVE».

## Размер (XS→XL) → масштаб команды
| Размер | Пример этого профиля | Команда |
|---|---|---|
| XS | быстрый grep секретов в 1 модуле | session-only: 1× @Researcher (`Explore`) |
| S/M | аудит auth-фичи + скан зависимостей | консилиум 3-4 линзы (см. ниже) → verify → report |
| L/XL | аудит всего репо + история git + лицензии | full консилиум + SubLead на под-домены, глубина 2 |

## Стадии (DAG)
`scope → scan → verify → report`
Переходы: линейно; **`verify → scan`** — откат при новой зоне/индикаторе. `report` — терминальная.
Persistent: `./swarm-report/<slug>-security-audit.md` (каждый finding: индикатор → доказательство `file:line`/commit → severity → verify-verdict → ремедиация).

## Сабагенты по стадиям
| Стадия | Роль → агент (base) | Модель | Цель |
|---|---|---|---|
| scope | @Researcher (`Explore`) / мейн | haiku | периметр: модули, точки входа, secrets-хранилища, deps-манифесты |
| scan | **консилиум 4× @Researcher (`Explore`) / @Reviewer** | sonnet | по линзе каждый (см. ниже), собрать индикаторы с `file:line`/commit |
| verify | @Reviewer (`general-purpose`) / мейн | opus | подтвердить эксплуатируемость, снять false-positive, назначить severity |
| report | мейн-оркестратор | sonnet | свести findings по severity + ремедиация |

**Base-агенты:** @Researcher→`Explore` · @Reviewer→`general-purpose` (+skill `superpowers:requesting-code-review`). Роль+стек+I/O-контракт — в промпте агента.

**Консилиум линз (scan, одним заходом):**
- **secrets** — API-ключи/токены/пароли/private keys в коде **И в истории git**; проверить `.gitignore`, `local.properties`/`BuildConfig`/env как правильный путь.
- **auth-flow** — авторизация/сессии/токены: хранение, срок жизни, refresh, проверки на границах, deeplink/auth-require, небезопасные дефолты (backend — authZ на каждом эндпоинте).
- **deps-CVE** — зависимости на известные CVE (версии из version-catalog/gradle/lockfile) + **лицензии** (копилефт/несовместимые).
- **OWASP** — инъекции (SQLi для backend), небезопасная десериализация, слабая крипта, cleartext-трафик, экспортированные компоненты, логирование чувствительных данных.

## MCP / Skills (обязательные)
`ast-index` (auth-поток: callers/границы) · **Grep + `git log -p`/`git log -S`** (секреты в коде и истории) · Context7/DeepWiki (актуальные CVE/безопасные версии — не по памяти) · **Sentry** (утечки в логах/стектрейсах, всплывшие эксепшены) · `./conventions.md` (где секреты/auth в проекте; base без project-context-скилла) · встроенный `/security-review` — как чек-лист.

## MUST (обязан)
- **Grep секретов в коде И в истории git** (`git log -S`, `-p`), не только в HEAD; засветившийся ключ → пометить как скомпрометированный + **рекомендовать ротацию**.
- Проверять **зависимости (CVE) + лицензии** через актуальные источники (Context7/DeepWiki), не по памяти.
- Проверять **auth-поток** end-to-end (хранение → передача → проверка на границах) и **Sentry** на утечки чувствительных данных в логах.
- **Verify** каждый finding (эксплуатируемость, false-positive) перед выдачей; назначить severity.

## MUST NOT (нельзя)
- **Эксплуатировать/эксфильтровать** — не выполнять реальные атаки, не выкачивать/не отправлять секреты наружу, не логировать значения ключей (только факт+локацию).
- **Менять код** — только отчёт + рекомендации по ремедиации (правки — отдельный профиль).
- Печатать полные значения найденных секретов; коммитить/пушить.
- Судить о CVE/версиях по памяти.

## Формат ответа
Findings сгруппированы по severity, каждый — `file:line`/commit + суть + **ремедиация**:
- **Critical** — активная утечка/дыра (утёкший ключ, обход авторизации, RCE-класс).
- **High** — серьёзно, требует срочного фикса (уязвимая dep с эксплойтом, cleartext auth).
- **Medium** — усилить (слабые дефолты, несовместимая лицензия, чувствительные логи).
- **Low** — hardening/гигиена.
Плюс сводка: скан-периметр, что проверено, что вне охвата. Пусто в секции — «— нет».

## Chaining (если апстрим)
Не апстрим; **conditional**: Critical/High → срочный фикс —
`Chaining: security-audit → bug-fix` (urgent-вариант, как incident) · утёкший секрет → отдельно **ротация ключа** (наружу — подтвердить у пользователя).
