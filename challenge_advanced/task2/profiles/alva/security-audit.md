# Профиль: Security-Audit — alva (KMM+CMP baby-care)

> Контекст **alva** (Kotlin Multiplatform + Compose Multiplatform, baby-care). Роли → сабагенты из `alva/roster.md`;
> общее — секции «Оркестрация»/«Стадии»/«Профили» глобального `~/.claude/CLAUDE.md` + `./conventions.md` (не дублировать).
> Стек: KMP · CMP (shared обе платформы) · Koin · Ktor · доки — **DeepWiki**. Build: `./gradlew :androidApp:assembleDebug` (+ Xcode iOS).

## Назначение / когда активен
**READ-ONLY аудит безопасности** — секреты, авторизация, зависимости/CVE, лицензии, OWASP-паттерны. Baby-care ⇒ **чувствительные данные ребёнка** — повышенный приоритет. Только отчёт + рекомендации.
Триггеры: «проверь на уязвимости», «security-аудит», «нет ли утёкших секретов», «проверь зависимости/лицензии/CVE», «безопасна ли авторизация».
Примеры: «нет ли захардкоженных ключей», «аудит auth-потока», «проверь deps на известные CVE».

## Размер (XS→XL) → масштаб команды
| Размер | Пример этого профиля | Команда |
|---|---|---|
| XS | быстрый grep секретов в 1 модуле | session-only: 1× `Explore` |
| S/M | аудит auth-фичи + скан зависимостей | консилиум 3-4 линзы (см. ниже) → verify → report |
| L/XL | аудит всего репо + история git + лицензии | full консилиум + SubLead на под-домены, глубина 2 |

## Стадии (DAG)
`scope → scan → verify → report`
Переходы: линейно; **`verify → scan`** — откат при новой зоне/индикаторе. `report` — терминальная.
Persistent: `./swarm-report/<slug>-security-audit.md` (каждый finding: индикатор → доказательство `file:line`/commit → severity → verify-verdict → ремедиация).

## Сабагенты по стадиям
| Стадия | Роль → сабагент | Модель | Цель |
|---|---|---|---|
| scope | @Researcher `Explore` / мейн | haiku | периметр: модули (common/android/ios), точки входа, secrets-хранилища, deps-манифесты (version catalog) |
| scan | **консилиум 4× `Explore` / `alva-review-expert`** | sonnet | по линзе каждый (см. ниже), собрать индикаторы с `file:line`/commit |
| verify | @Reviewer `alva-review-expert` / мейн | opus | подтвердить эксплуатируемость, снять false-positive, назначить severity |
| report | мейн-оркестратор | sonnet | свести findings по severity + ремедиация |

**Консилиум линз (scan, одним заходом):**
- **secrets** — API-ключи/токены/пароли/private keys в коде **И в истории git**; проверить `.gitignore`, `local.properties`/`BuildConfig`/env как правильный путь (на обеих платформах, включая iOS `plist`/entitlements).
- **auth-flow** — авторизация/сессии/токены: хранение (DataStore/Keychain), срок жизни, refresh, проверки на границах, deeplink/auth-require, небезопасные дефолты; **данные ребёнка** — шифрование/приватность.
- **deps-CVE** — зависимости на известные CVE (версии из **version-catalog**/gradle) + **лицензии** (копилефт/несовместимые); KMP-зависимости на обеих платформах.
- **OWASP** — инъекции, небезопасная десериализация (kotlinx-serialization), слабая крипта, cleartext-трафик (Ktor), экспортированные компоненты, логирование чувствительных данных (Napier).

## MCP / Skills (обязательные)
`ast-index` (auth-поток: callers/границы) · **Grep + `git log -p`/`git log -S`** (секреты в коде и истории) · **DeepWiki** (актуальные CVE/безопасные версии — не по памяти) · **Sentry** (утечки в логах/стектрейсах) · `alva-project-context` (где секреты/auth в проекте) · встроенный `/security-review` — как чек-лист.

## MUST (обязан)
- **Grep секретов в коде И в истории git** (`git log -S`, `-p`), не только в HEAD; засветившийся ключ → пометить как скомпрометированный + **рекомендовать ротацию**.
- Проверять **зависимости (CVE) + лицензии** через актуальные источники (DeepWiki), не по памяти; учесть обе платформы.
- Проверять **auth-поток** end-to-end (хранение → передача → проверка на границах) и **Sentry** на утечки чувствительных данных ребёнка в логах.
- **Verify** каждый finding (эксплуатируемость, false-positive) перед выдачей; назначить severity.

## MUST NOT (нельзя)
- **Эксплуатировать/эксфильтровать** — не выполнять реальные атаки, не выкачивать/не отправлять секреты наружу, не логировать значения ключей (только факт+локацию).
- **Менять код** — только отчёт + рекомендации по ремедиации (правки — отдельный профиль).
- Печатать полные значения найденных секретов; коммитить/пушить.
- Судить о CVE/версиях по памяти.

## Формат ответа
Findings сгруппированы по severity, каждый — `file:line`/commit + суть + **ремедиация**:
- **Critical** — активная утечка/дыра (утёкший ключ, обход авторизации, утечка данных ребёнка, RCE-класс).
- **High** — серьёзно, требует срочного фикса (уязвимая dep с эксплойтом, cleartext auth).
- **Medium** — усилить (слабые дефолты, несовместимая лицензия, чувствительные логи).
- **Low** — hardening/гигиена.
Плюс сводка: скан-периметр (платформы), что проверено, что вне охвата. Пусто в секции — «— нет».

**Маркировка прогресса — обязательна на каждом шаге task execution:**
- **Старт шага:** `▶️ **ШАГ <n>/<N> · <стадия>** — <название шага>`
- **Задача шага:** `🎯 **Задача:** <что именно делаем — одна строка>`
- **Итог шага:** `✅ **Итог:** <главная мысль>` · провал — `❌ **Провал:** <что сломалось + где>` · частично — `⚠️ **Частично:** <что осталось>`
- **Переход стадии:** `🔀 **Переход:** <стадия> → <стадия>` · чейнинг — `⛓️ **Chaining:** <profile> → <profile>`

Каждая метка — отдельной строкой, иконка + **жирный** лейбл, не сливать с прозой. Между шагами — `---`.
Без маркировки шаг считается незакрытым.

## Chaining (если апстрим)
Не апстрим; **conditional**: Critical/High → срочный фикс —
`Chaining: security-audit → bug-fix` (urgent-вариант, как incident) · утёкший секрет → отдельно **ротация ключа** (наружу — подтвердить у пользователя).
