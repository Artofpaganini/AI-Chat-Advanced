# Профиль: research — xbet

> Контекст **xbet** (`Mobile_Android_OnexBet`); также обслуживает twin **xbet1** (`own_xbet`).
> Android-only · **Dagger 2** · **Cicerone `XPlatformRouter`** · UDF со **SideEffect** · MCP-доки **Context7**.
> Стек/сабагенты — `roster.md`. Общее — `../_shared/orchestration.md` и `../_shared/conventions.md` (не дублировать).

## Назначение / когда активен
**READ-ONLY разведка кодовой базы и ответ на вопросы о ней** — без изменений кода.
Триггеры: «как устроено…», «как работает…», «где…», «карта/схема…», «какие … не покрыты…», «что вызывает…», «зависимости …».
Примеры: «как устроена авторизация», «какие эндпоинты не покрыты тестами», «карта подсистемы X», «кто вызывает `SyncManager`».

## Размер (XS→XL) → масштаб команды
| Размер | Пример этого профиля | Команда |
|---|---|---|
| XS | «где определён класс X», один файл/символ | session-only: 1× `Explore` (или ast-index напрямую) |
| S/M | «как устроена авторизация», карта одной подсистемы | консилиум 2-4× `Explore` (разные линзы) → синтез мейном |
| L/XL | карта всего домена/кросс-модульный поток, аудит покрытия | full консилиум (4 линзы) + SubLead на под-домены, глубина 2 |

## Стадии (DAG)
`scope → parallel-search → synthesize → answer`
Переходы: линейно; **`synthesize → parallel-search`** — откат, если completeness-critic нашёл непокрытое (добор линз/зон). `answer` — терминальная.
Persistent: `./swarm-report/<slug>-research.md` (гипотезы, найденные `file:line`, что уже проверено `[x]`, открытые вопросы).

## Сабагенты по стадиям
| Стадия | Роль (subagent) | Модель | Цель |
|---|---|---|---|
| scope | `Explore` / мейн | haiku | очертить границы вопроса, зоны поиска, критерии «ответ полон» |
| parallel-search | **консилиум 4× `Explore`** | sonnet | по линзе каждый (см. ниже), вернуть `file:line`-факты, не выводы |
| synthesize | мейн-оркестратор | opus | склеить факты в карту, разрешить конфликты линз |
| answer + completeness-critic | `Explore` / мейн | sonnet | сформулировать ответ + отдельно «что НЕ проверено / слепые зоны» |

**Консилиум линз (parallel-search, одним заходом, диверсити > избыточность):**
- **by-container** — по модулям/каталогам/пакетам: где физически лежит подсистема.
- **by-content** — free-text/семантика: строки, конфиги, endpoint-пути, флаги (Grep-линза).
- **by-entity** — по сущностям/символам: классы, интерфейсы, модели, их иерархия (ast-index).
- **by-callers** — потоки вызовов: callers/callees, Dagger-граф, кто дергает кого (ast-index usages).

## MCP / Skills (обязательные)
`ast-index` (by default — класс/символ/usages/callers/module-deps/структура; `update` НЕ звать) · Grep — только free-text · **Context7** — при вопросах про библиотечное поведение · `xbet-project-context` · `xbet-reference-modules` · Sentry — если вопрос про рантайм-ошибки/краши.

## MUST (обязан)
- **Read-only.** ast-index — первый инструмент поиска, Grep — фолбэк на free-text.
- Каждый факт/утверждение — с **точной цитатой `file:line`** (относительные к корню репо → в ответе абсолютные пути).
- Читать реальный код перед выводом — **не гадать по имени файла/символа**.
- Завершать **completeness-critic**: явный раздел «что НЕ проверено / где возможны слепые зоны / допущения».
- Консилиум — разными линзами (by-container/content/entity/callers), не N одинаковых прогонов.

## MUST NOT (нельзя)
- **Менять ЛЮБОЙ код / файлы проекта** (кроме своего persistent-файла в `swarm-report/`).
- Отвечать по памяти о версиях/API библиотек — только Context7.
- Выдавать вывод без подтверждающего `file:line`; строить ответ на догадках.
- Расширять задачу до правок/рефактора — это отдельный профиль (см. Chaining).

## Формат ответа
1. **Файлы** — список с абсолютными путями + `:line`, роль каждого одной строкой.
2. **Связи / поток** — как компоненты взаимодействуют (вызовы, Dagger, данные); при пользе — ASCII/mermaid.
3. **Выводы** — прямой ответ на вопрос, кратко.
4. **Открытые вопросы / не проверено** — completeness-critic: слепые зоны, допущения, что стоит доразведать.

## Chaining (если апстрим)
Не апстрим по умолчанию (терминальный ответ). Если находка требует действия — объявить и передать карту как вход:
`Chaining: research → bug-fix` (нашли дефект) · `research → refactor|architecture` (структурная проблема) · `research → test` (пробел покрытия, opt-in).
