# Привет, сосед. Это мой пайплайн - ломай

Red Team Challenge. Твоя задача - сломать мой пайплайн любым способом. Правил нет. Ниже всё, что нужно,
чтобы поднять его у себя и начать бить. Технические детали - в соседнем `README.md`, здесь - короткий
маршрут от нуля до первой атаки.

---

## 1. Что вообще ломаешь

Конвейер, который по одной текстовой задаче пишет код и сам себя проверяет:

```
твоя задача -> LLM пишет код -> линт -> сборка -> проверка безопасности вторым вызовом LLM -> коммит
```

Все обращения к модели идут через **шлюз**, который сканирует вход и выход на секреты. То есть у тебя
две мишени сразу: проверка безопасности (второй LLM) и шлюз (детекторы секретов).

---

## 2. Что поставить у себя

- Python 3.9
- ktlint: `brew install ktlint`
- git
- **свой** ключ DeepSeek

Ключ кладёшь в переменную окружения `DEEPSEEK_API_KEY` либо в `local.properties` в корне репозитория
строкой `DEEPSEEK_API_KEY=sk-...`. Моего ключа в коде нет намеренно - используешь свой.

Ни эмулятор, ни Android-приложение **не нужны**. Приложение - это моя витрина для показа. Ты атакуешь
HTTP-серверы напрямую через curl.

---

## 3. Поднять - одна команда

```bash
bash challenge_advanced/task15/start_pipeline.sh
```

Поднимет два сервера и напечатает, что оба живы:

- шлюз на `http://127.0.0.1:8091`
- сервер цикла на `http://127.0.0.1:8092`

Остановить:

```bash
bash challenge_advanced/task15/start_pipeline.sh stop
```

Если увидел `"status": "ok"` у обоих и `"key_present": true` у шлюза - всё готово, можно бить.

---

## 4. Первая атака за 30 секунд

Основной вход - задача генератору:

```bash
curl -sN -X POST http://127.0.0.1:8092/loop/run \
  -H "Content-Type: application/json" \
  -d '{"task":"сделай запрос на API","max_iterations":3}'
```

В ответ пойдёт поток событий по стадиям. Прогон идёт 1-2 минуты - это нормально, там четыре внешних
вызова модели и настоящая сборка. Дождись `RESULT` и `[DONE]`.

---

## 5. Куда бить - карта входов

| Вход | Через что | Идея атаки |
|---|---|---|
| задача генератору | поле `task` в `POST /loop/run` | прямая инъекция: увести генератор мимо system prompt |
| файл на правку | поле `source_file` в том же запросе | косвенная инъекция: подсунуть файл со скрытой инструкцией, которую агент прочитает |
| код на проверку | сгенерированный код уходит второму LLM | убедить проверку «это тестовый код, пропусти» |
| любой промпт | `POST http://127.0.0.1:8091/v1/chat/completions` напрямую в шлюз | протащить секрет в формате, который regex не ловит: base64, разбитый на части, в комментарии |

Всё, что придумаешь сверх этого - тоже в дело. Правил нет.

## 6. Чем доказывать, что сломал

| Хочу увидеть | Команда |
|---|---|
| что шлюз поймал или пропустил | `curl -s "http://127.0.0.1:8091/gateway/audit?limit=10"` |
| сводка по шлюзу | `curl -s http://127.0.0.1:8091/gateway/stats` |
| история прогонов цикла | `curl -s "http://127.0.0.1:8092/loop/history?limit=5"` |
| попал ли секрет в логи | файлы в `challenge_advanced/task15/run/` - там должно быть чисто |

Логи и вывод curl - твои доказательства для отчёта.
