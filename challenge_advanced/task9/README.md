# Task9 - декомпозиция инференса

Тот же триаж сообщения родителя, что в task7 и task8, но теперь как цепочка из трёх коротких
запросов вместо одного большого. Проверяем, окупается ли разделение задачи на разбор, решение и
ответ - и где именно у декомпозиции проходит настоящая граница.

**Главный результат:** для этого триажа декомпозиция не окупается - монолит точнее, дешевле и
быстрее. Смешивание моделей по этапам (слабая на разборе и ответе, сильная на решении) частично
закрывает разрыв в точности, но не бесплатно и не чинит главный дефект - тот живёт на этапе разбора,
а не на этапе решения.

## Что где лежит

| Файл | Что делает |
|---|---|
| `harness/stages_spec.py` | Константы: промпты трёх этапов, имена полей, лимиты, коды нарушений |
| `harness/stages.py` | `run_monolithic` и `run_multistage` - сама логика обоих вариантов |
| `harness/run_stages.py` | Прогон набора кейсов, оба варианта, модели по этапам настраиваются флагами |
| `harness/stages_report.py` | Метрики, разбивка по группам, проверка гипотез, гейт по пропущенным экстренным |
| `harness/show_case.py` | Показывает один кейс насквозь: монолит и все три этапа, с ценой, токенами и нарушениями формата каждого шага |

`show_case.py` - самый быстрый способ посмотреть на задачу глазами, без чтения сырых `jsonl`:

```bash
python3 harness/show_case.py borderline_01               # из raw/ по умолчанию
python3 harness/show_case.py borderline_01 --runs raw/mixed  # смешанные модели по этапам
```

Он ничего не считает и не ходит в сеть - только читает готовое сырьё из `raw/` и печатает сообщение
родителя, ответ монолита, вывод каждого из трёх этапов цепочки и разницу в цене и времени между
ними.

### Данные и замеры

| Путь | Что |
|---|---|
| `../task7/data/cases.jsonl` | те же 50 кейсов, что и в task7 - task9 своих не заводит |
| `raw/monolithic_runs.jsonl`, `raw/multistage_runs.jsonl` | основной прогон, одна модель на всём |
| `raw/r2/`, `raw/r3/` | повторы 2 и 3 того же прогона - решение принимается по всем трём, не по одному |
| `raw/mixed/` | цепочка со смешанными моделями по этапам, три повтора - `REPORT.md` разд. 8 |
| `results/stages_report.json` | агрегат по трём прогонам одномодельного сравнения |
| `results/stages_report_mixed.json` | агрегат монолита против смешанной цепочки |

## Быстрый запуск

```bash
cd challenge_advanced/task9

# план вызовов и оценка стоимости, без сети
python3 harness/run_stages.py --dry-run --mode both

# основной прогон, ключ берётся из окружения либо из local.properties
python3 harness/run_stages.py --mode both --workers 4

# суммарно по всем трём прогонам (raw/, raw/r2/, raw/r3/) - так считаются числа в REPORT.md
python3 harness/stages_report.py --runs raw raw/r2 raw/r3 --out results/stages_report.json

# посмотреть один кейс насквозь
python3 harness/show_case.py borderline_01
```

Эксперимент со смешанными моделями по этапам и все команды повторов - `REPORT.md` раздел 9.

## Что важно знать

- **Гипотезы записаны в `SPEC.md` до первого замера** и не переписывались после результата -
  меняются только вердикты, если в вычислении находится ошибка (пример - `REPORT.md` разд. 3).
- **Точность считается суммарно по всем кейсам всех прогонов**, не медианой per-run значений - иначе
  можно принять случайный разброс между прогонами за реальную разницу между вариантами.
- **Живой чат (`../task7/harness/triage_server.py`) работает на монолитном варианте**, не на
  цепочке. Декомпозиция измеряется только харнессом этой задачи - подробности `RESULT.md`, шаг 3.
- **Ключ только из окружения или `local.properties`**, который в `.gitignore`.
