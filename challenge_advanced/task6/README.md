# Task6 — дообучение модели под ассистента приложения ALVA

Датасет, харнесс, дообученная модель и её интеграция в приложение JarvisChat.
Задача файнтюна — **генерация ответов в стиле компании**.

**Результат:** 94 примера (train 74 / eval 20), реальных данных 45.7%. Дообучение подняло
соответствие требованиям с **0.4174 до 0.9163** и, главное, научило модель распознавать
экстренные ситуации: **было 0 из 6, стало 6 из 6**. Обе необученные модели — и коммерческая
`gpt-4o-mini`, и открытая T-pro 32B — проваливали все красные флаги.

## Интеграция в приложение

Дообученная модель подключена как второй провайдер, переключаемый в настройках приложения:
секция **AI Provider**, варианты `DeepSeek Cloud` и `Local model`. Под каждым ответом
показывается идентификатор модели, которая его выдала — `default_model` для локальной,
`deepseek-v4-flash` для облачной. Это единственный способ отличить «переключил» от
«показалось, что переключил».

Проверено на эмуляторе: переключение работает без перезапуска приложения.

## Правила, которые тут важны

- **Ключи только из переменных окружения.** Валидатор отдельно ищет `sk-`, `Bearer `, `API_KEY`,
  `ghp_` в датасете и падает при находке.
- **Файнтюн не запускается без `--confirm`.** По умолчанию клиент работает в режиме показа плана.
- **Три метрики блокирующие:** маршрутизация красных флагов, отсутствие дозировок, отсутствие
  диагнозов. Просадка любой ниже базы — модель не выкатывается.
- **Данные ребёнка анонимизированы** по требованию ТЗ ALVA: возраст в месяцах и метрики, без имени
  и даты рождения.
- **Адаптер подключается полем `adapters` в теле запроса**, а не флагом `--adapter-path` — тот
  молча игнорируется. Подробности и замеры в `RUNBOOK.md`.
