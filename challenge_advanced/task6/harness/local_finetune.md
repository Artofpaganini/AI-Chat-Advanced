# Локальный файнтюн ассистента ALVA - LoRA на Apple Silicon

Инструкция по дообучению на своей машине через `mlx-lm`: LoRA поверх 4-битной базы (Q-LoRA).
Датасет тот же, что готовился под OpenAI - `artifacts/train.jsonl` и `artifacts/eval.jsonl`,
меняется только раскладка файлов.

---

## 1. Зачем локально

Облачный путь закрылся не по нашей вине. Что осталось у провайдеров:

| Провайдер | Файнтюн | Что мешает |
|---|---|---|
| OpenAI | закрыт | self-serve свернули: на `POST /v1/fine_tuning/jobs` приходит 403 «winding down the fine-tuning platform» |
| DeepSeek | нет | публичного API дообучения не публиковали, только инференс |
| OpenRouter | нет | это роутер инференса, своих весов он не обучает |
| Anthropic | нет | дообучения не даёт вообще, только промптинг и кеш |
| Локально, `mlx-lm` | **есть** | единственный оставшийся путь, всё считается на своей машине |

Плюс локального пути: ключи никуда не уходят, данные ребёнка не покидают машину, стоимость нулевая.
Минус: база слабее коммерческой, и это надо честно учитывать при сравнении (раздел 4).

---

## 2. Что нужно

| Требование | Значение |
|---|---|
| Железо | Apple Silicon (проверялось на M4 Pro), 48 ГБ объединённой памяти |
| ОС | macOS с Metal, Python 3.9+ для харнесса, Python 3.11 в venv для `mlx-lm` |
| Пакеты | `mlx-lm` (тянет `mlx`, `transformers`, `huggingface-hub`) |
| База | `mlx-community/Qwen2.5-7B-Instruct-4bit`, около 4.5 ГБ на диске |
| Свободное место | около 10 ГБ: веса, кеш HuggingFace, адаптеры |
| Время | обучение 200 итераций - десятки минут, не часы |

Почему именно Qwen2.5-7B-Instruct в 4 битах: есть готовая MLX-сборка, русский держит приемлемо,
в 4 битах помещается с большим запасом по памяти, а инструкт-версия уже умеет следовать шаблону.

Установка окружения:

```bash
uv venv --python 3.11 .venv-mlx
uv pip install --python .venv-mlx/bin/python mlx-lm
source .venv-mlx/bin/activate
```

Проверка, что всё встало:

```bash
mlx_lm.lora --help
```

Если окружение уже собрано в другом месте, активировать надо его, а не создавать новое - команды
ниже одинаковы. Проверялась версия `mlx-lm` 0.31.3, флаги ниже сверены с её `--help`.

## 3. Шаги

Все команды выполняются из корня задачи:

```bash
cd /Users/Victor/AI-Chat-Advanced/challenge_advanced/task6
```

### Шаг 1. Конвертация датасета

```bash
python3 harness/to_mlx.py
```

Скрипт кладёт в `artifacts/mlx_data/` три файла, которые ждёт `mlx_lm.lora`:

| Файл | Строк | Откуда | Роль |
|---|---|---|---|
| `train.jsonl` | 59 | `artifacts/train.jsonl` минус valid | на нём считается градиент |
| `valid.jsonl` | 15 | отрезано от `artifacts/train.jsonl`, seed 1337 | validation loss по ходу обучения |
| `test.jsonl` | 20 | копия `artifacts/eval.jsonl` | в обучении не участвует, точка замера |

Формат строки не меняется: `{"messages": [system, user, assistant]}` - это нативный chat-формат
`mlx-lm`, он совпадает с форматом OpenAI. Конвертер только перекладывает и валидирует.

Доля valid и seed настраиваются: `--valid-ratio 0.15 --seed 42`. Каталог назначения - `--out DIR`.

### Шаг 2. Обучение

```bash
mlx_lm.lora \
  --model mlx-community/Qwen2.5-7B-Instruct-4bit \
  --train \
  --data artifacts/mlx_data \
  --batch-size 2 \
  --iters 200 \
  --num-layers 8 \
  --learning-rate 1e-4 \
  --max-seq-length 2048 \
  --mask-prompt \
  --steps-per-eval 25 \
  --val-batches -1 \
  --save-every 50 \
  --seed 1337 \
  --adapter-path artifacts/mlx_adapters/alva-qwen-lora
```

Что делает каждый ключ и почему выбрано такое значение:

| Ключ | Значение | Одной строкой |
|---|---|---|
| `--model` | `mlx-community/Qwen2.5-7B-Instruct-4bit` | база в 4 битах, скачается в кеш HuggingFace при первом запуске |
| `--train` | флаг | без него скрипт ничего не обучает |
| `--data` | `artifacts/mlx_data` | каталог с `train/valid/test.jsonl` из шага 1 |
| `--batch-size` | 2 | на 59 примерах это около 30 шагов на эпоху, при 4 шагов вдвое меньше и обучение грубее |
| `--iters` | 200 | 200 x 2 / 59 - около 6.8 эпохи, рабочий коридор для LoRA на стиль |
| `--num-layers` | 8 | дообучаем 8 верхних блоков из 28: меньше параметров - меньше шансов переучиться на 59 примерах |
| `--learning-rate` | 1e-4 | дефолтный 1e-5 за 200 итераций не успевает сдвинуть стиль |
| `--max-seq-length` | 2048 | самый длинный пример около 2100 символов, это примерно 1000 токенов - обрезки не будет |
| `--mask-prompt` | флаг | loss считается только по ответу ассистента, модель не учится копировать вопрос родителя |
| `--steps-per-eval` | 25 | восемь замеров validation loss за прогон, видно момент разворота вверх |
| `--val-batches` | -1 | считать на всём valid, он крошечный |
| `--save-every` | 50 | промежуточные адаптеры, чтобы можно было вернуться к менее переученному |
| `--seed` | 1337 | воспроизводимость прогона |
| `--adapter-path` | `artifacts/mlx_adapters/alva-qwen-lora` | куда лягут веса адаптера, дефолт `adapters/` в текущем каталоге |

На что смотреть в логе: `Train loss` должен падать, `Val loss` - падать и не разворачиваться вверх.
Разворот вверх = переобучение, берите чекпоинт с меньшего числа итераций из `--adapter-path`.

Дополнительно, только если память всё-таки кончилась: `--grad-checkpoint`, `--batch-size 1`,
`--num-layers 4`. На 48 ГБ с 4-битной базой это не должно понадобиться.

Опционально после обучения можно посчитать loss на отложенном `test.jsonl` - добавьте `--test`.
Это только loss, конвенции им не измеряются, их считает `harness/score.py`.

### Шаг 3. Сервер с адаптером

```bash
mlx_lm.server \
  --model mlx-community/Qwen2.5-7B-Instruct-4bit \
  --adapter-path artifacts/mlx_adapters/alva-qwen-lora \
  --port 8080
```

Хост по умолчанию `127.0.0.1`, порт по умолчанию `8080`, то есть базовый URL -
`http://127.0.0.1:8080/v1`. API OpenAI-совместимый, авторизацию сервер не проверяет вообще,
поэтому ключ подойдёт любой непустой.

**Важная ловушка.** Сервер берёт имя модели из поля `model` в теле запроса. Значение по умолчанию -
строка `default_model`, и только для неё подставляются `--model` и `--adapter-path` из командной
строки. Если прислать `"model": "mlx-community/Qwen2.5-7B-Instruct-4bit"`, сервер загрузит базу
**без адаптера** и молча ответит как необученная модель. Поэтому в запросах к дообученной модели
поле `model` должно быть ровно `default_model`.

### Шаг 4. Замер через харнесс

```bash
export LOCAL_API_KEY=local-no-auth
python3 harness/baseline_run.py --provider local --n 20 --out raw/qwen_lora_local.jsonl
python3 harness/score.py raw/qwen_lora_local.jsonl
```

**Отдельный шаг для координатора: в `harness/baseline_run.py` профиля `local` пока нет.**
Сейчас там три профиля - `openrouter`, `deepseek`, `openai`. Правку этого файла в текущей задаче
не делали намеренно, чтобы не трогать код, которым уже снят baseline. Что нужно добавить в
`PROVIDER_PROFILES`:

| Поле | Значение | Зачем |
|---|---|---|
| `base_url` | `http://127.0.0.1:8080/v1` | локальный `mlx_lm.server`, скрипт сам добавит `/chat/completions` |
| `model` | `default_model` | иначе адаптер не подхватится, см. ловушку в шаге 3 |
| `key_env` | `LOCAL_API_KEY` | скрипт требует непустой ключ, сервер его игнорирует |
| `supports_seed` | `True` | сервер поле `seed` принимает |
| `extra_headers` | `{}` | ничего дополнительного не нужно |

Проверить профиль без сети: `python3 harness/baseline_run.py --provider local --dry-run`.

## 4. Честное сравнение

Сравнивать `conventions_score` дообученного Qwen с baseline на `gpt-4o-mini` нельзя: это разные
модели, разного размера, у одной ещё и квантование. Такое сравнение измеряет разницу моделей,
а не эффект дообучения.

Нужны две точки на **одной и той же базе**:

| Точка | Как снять | Что показывает |
|---|---|---|
| A. Qwen без адаптера | сервер запущен **без** `--adapter-path`, затем `baseline_run.py --provider local --n 20 --out raw/qwen_base_local.jsonl` | на что способна база сама по себе |
| B. Qwen с адаптером | сервер с `--adapter-path`, затем тот же прогон в `raw/qwen_lora_local.jsonl` | что добавил файнтюн |

Эффект дообучения = B минус A. Оба прогона идут по одному `artifacts/eval.jsonl`, с одним
системным промптом, одной температурой и одним seed - иначе сравнение снова разъедется.

Замер на `gpt-4o-mini` (средний score 0.4517) остаётся третьей, справочной точкой: он отвечает на
другой вопрос - «насколько коммерческая модель без дообучения попадает в наш формат». В одну
таблицу с A и B его ставить можно, но с явной пометкой, что база другая.

Отдельно смотрим три блокирующие метрики: `red_flag_routing`, `no_dosage`, `no_diagnosis`.
Просадка любой из них в точке B относительно точки A - повод адаптер забраковать, даже если
средний score вырос.

## 5. Риски и ограничения

| Риск | Суть | Что делать |
|---|---|---|
| Мало данных | 59 обучающих примеров - очень мало для LoRA, переобучение почти неизбежно | следить за `Val loss`, брать ранний чекпоинт, держать `--num-layers` маленьким |
| Заучивание | на такой выборке модель может запоминать конкретные ответы вместо стиля | проверять на `test.jsonl`, который в обучении не участвовал |
| Квантование | 4 бита - это потеря качества относительно fp16 базы | помнить при чтении цифр, при желании сравнить с 8-битной сборкой |
| Русский у 7B | 7B держит русский заметно слабее коммерческих моделей: падежи, согласование, канцелярит | часть просадки score - это язык, а не формат |
| Ловушка `model` | запрос с полным именем модели грузит базу без адаптера | в профиле `local` держать `model = default_model` |
| Локаль | `mlx-lm` открывает jsonl без явной кодировки, при `LANG=C` кириллица развалится | `export LANG=ru_RU.UTF-8` или `en_US.UTF-8` перед запуском |
| Первый запуск | база тянется из сети, около 4.5 ГБ | заранее прогреть кеш, не запускать обучение на плохом канале |

Главное ограничение: это **учебная демонстрация метода**, а не продовое решение. Прод для ALVA -
это коммерческая модель с промптингом и валидатором формата на выходе, либо файнтюн на выборке
на порядок больше и с медицинской вычиткой каждого ответа.
