# Task6 — отчёт: дообучение модели под ассистента приложения ALVA

Ветка `task6`. Роль модели — ассистент-педиатр-психолог для родителей детей 0-3 лет,
встраивается в приложение **ALVA** (кнопка ИИ в центре нижнего меню, ТЗ v1.0).

---

## 2. Выбор задачи

Из трёх вариантов — классификация, генерация, extraction — взята **генерация ответов в стиле
компании**.

Причина не в том, что базовые модели плохо знают педиатрию. Знают неплохо. Причина в двух вещах,
которые промптом держатся ненадёжно:

1. **Формат.** ТЗ ALVA (стр. 28-29) требует: объяснение ≤100 слов, рекомендации 3-5 штук по ≤25 слов,
   без диагнозов. Замер показал: базовая модель не выполнила ни одного из шести правил структуры
   ни разу за 20 попыток.
2. **Приоритет в опасной ситуации.** Главный результат работы, см. раздел 7.

### Реальные данные — 43 примера (45.7%)

Реальным считается пример, у которого и вопрос, и фактура ответа опираются на проверяемый источник,
указанный в поле `source`.

| Источник | Что взято |
|---|---|
| ТЗ ALVA v1.0 с номером страницы | Формулы `TotalScore`, `GrowthScore`, `SleepScore`, поля JSON ребёнка, 12 скачков, календарь-гармонизатор, анамнез-репорт |
| Рекомендации ВОЗ | ГВ примерно до 6 месяцев, прикорм около 6 месяцев, нормы сна, прибавка веса, перцентили, безопасный сон |
| Публичные клинические рекомендации | Красные флаги: батарейка, магниты, ожоги, отравления, анафилаксия, менингеальные признаки, инвагинация, обезвоживание |

Честная оговорка: это не «реальные диалоги из прода» — приложения в проде нет. Реальность здесь
в источнике фактуры и в том, что продуктовые сценарии взяты из настоящего ТЗ.

### Вход ассистента

По ТЗ (стр. 18) данные проходят через сервис анонимизации. Поэтому `user` несёт блок с
анонимизированным JSON:

```
[child_context]
{"age_months": 5, "gender": "female", "weight": 6800, "height": 63,
 "family_battery": 72, "feeding_score": 81, "sleep_score": 64}
[/child_context]

Дочка стала спать заметно меньше. Я не понимаю, что мы делаем не так.
```

Персональных данных ребёнка нет ни в одном примере.

## 4. Чистка и валидация

```
сырьё: 94 строк
отброшено: 0
итог: 94 (train 74 / eval 20)
реальных: 43 (45.7%)
```

Ноль отбраковки — не потому, что пайплайн бездействует, а потому что каждый генератор прогонял свой
файл через те же правила перед сдачей. Работоспособность проверена отдельно на фикстурах: из 7
подсунутых строк выброшены 4 — пустая, короткая, дубль и строка со score ниже 1.0.

Валидатор на обоих файлах: **0 ошибок, 0 предупреждений, код возврата 0.** Отдельно проверяется,
не затесались ли в датасет ключи и токены — датасет уезжает во внешние сервисы.

Проверено по странице депрекейшенов OpenAI:

| Дата | Что происходит |
|---|---|

Организация новая, джоб в ней ноль — попадает под первую строку, и это необратимо. Загруженные

**Для задания это ничего не ломает** — там сказано «пока не запускайте, только подготовьте код».
Более того, отказ доказал, что клиент рабочий: авторизация прошла, оба файла загрузились,
эндпоинт ответил. Отказ пришёл от политики провайдера, а не от кода.

## 6. Локальное дообучение

Раз облачный путь закрыт, дообучение сделано локально на MacBook M4 Pro, 48 ГБ.

| | |
|---|---|
| База | `drammich/T-pro-it-2.1-4bit` — 32.8B, Qwen3, 64 слоя, 4 бита |
| Почему она | Русский — целевой язык, свой ru-токенизатор, режим без «размышлений» (шаблон не поедет), Apache 2.0 |
| Метод | LoRA поверх 4-битной базы, то есть **Q-LoRA** из лекции |
| Параметры | rank 16, scale 2.0, dropout 0.05, 16 слоёв из 64, lr 1e-4, batch 2, `--mask-prompt` |
| Обучаемых параметров | 33.5 млн из 32.8 млрд — **0.102%** |
| Пик памяти | 21.6 ГБ из 48 |
| Время | 1 час 40 минут, 250 итераций |
| Стоимость | **0** |

### Кривая обучения

```
Iter   1: Val loss 2.661
Iter  25: Val loss 1.438   <- минимум
Iter 100: Val loss 1.859   Train loss 0.072
Iter 250: Val loss 2.217   Train loss 0.002
```

Переобучение наступило за **25 итераций — меньше одной эпохи**. Train loss ушёл в 0.002: модель
выучила 59 обучающих примеров наизусть. Изначальный расчёт на 100-150 итераций был завышен вчетверо.

## 7. Результаты

| Модель | Средний score | Красные флаги | Примеров с 1.0 |
|---|---|---|---|
| `gpt-4o-mini`, без тюна | 0.4693 | **0 из 6** | 0 из 20 |
| T-pro 32B, без тюна | 0.4174 | **0 из 6** | 0 из 20 |
| **T-pro + LoRA (чекпоинт 25)** | **0.9163** | **6 из 6** | 8 из 20 |
| T-pro + LoRA (чекпоинт 100) | 0.9784 | 5 из 6 | 17 из 20 |
| T-pro + LoRA (чекпоинт 250) | 0.9731 | **6 из 6** | 17 из 20 |

**Прирост +0.50 абсолютных при пороге приёмки +0.25.**

По формату разгром: было 0 из 20 по структуре, счёту пунктов и их длине — стало 18-19 из 20.
Дисклеймер и блок «Когда к врачу» — было 0 и 1, стало 14 из 14 применимых.

### Главный результат

Обе необученные модели провалили **все шесть** экстренных сценариев: дисковая батарейка, магнитные
шарики, судороги, менингеальные признаки, обезвоживание, не бледнеющая сыпь. Ни коммерческая
`gpt-4o-mini`, ни открытая T-pro не дали номер экстренной службы и не обозначили срочность.

После дообучения — **6 из 6**.

Базовые модели **не опасны по составу**: дозировок нет (20 из 20), диагнозов нет (20 из 20).
Они **опасны по приоритету** — не отличают ситуацию, где счёт идёт на часы, от обычного вопроса.
Дообучение на 59 примерах это исправило.

## 8. Выбор чекпоинта и проверка на зубрёжку

Val loss вырос втрое, но качество не упало — чекпоинт 250 оказался не хуже 25-го. Чтобы понять,
не иллюзия ли это, прогнан тест: берём примеры, **которые модель видела при обучении**, подменяем
в них все числа и смотрим, какие цифры окажутся в ответе.

| | Читает вход | Запомнил | Смешанно | Без чисел |
|---|---|---|---|---|
| Чекпоинт 25 | 5 | **0** | 3 | 2 |
| Чекпоинт 250 | 6 | **0** | 2 | 2 |

Зубрёжки нет ни у одного.

**Отдельный вывод, который стоит запомнить: на задаче обучения формату val loss оказался плохим
показателем качества.** Он меряет дословное совпадение токенов с эталоном; модель ушла от
формулировок эталона, но структуру и поведение усвоила. Прямой замер по чек-листу честнее.

Разница между чекпоинтами 25 и 250 — 5.7 процентных пункта на выборке из 20 примеров, что внутри
объявленного порога значимости. При ничьей взят **чекпоинт 25**: минимум val-loss, вчетверо дешевле
по времени, меньше подогнан под обучающую выборку.

### Как запустить дообученную модель

```bash
mlx_lm.generate --model drammich/T-pro-it-2.1-4bit \
  --adapter-path ~/models/alva-tpro-lora-ckpt25 --prompt "..."
```

## 11. Интеграция в приложение JarvisChat

Дообученная модель подключена к приложению как второй провайдер, переключаемый в настройках.

### Что работает

| Элемент | Реализация |
|---|---|
| Переключатель в UI | Третья секция в шторке настроек: `DeepSeek Cloud` / `Local model`, выбор сохраняется между запусками |
| Смена адреса, модели, промпта | Доменная модель `AiProviderConfigModel` — базовый URL, идентификатор модели, системный промпт, признак ключа и путь к адаптеру меняются одним переключением |
| Чтение выбора | Провайдер читает настройку **при каждом запросе**, а не при старте — переключение работает без перезапуска приложения |
| Слой данных | Не дублировался: оба API OpenAI-совместимы, датасорс один |
| Сеть на Android | Незашифрованный HTTP разрешён только для `127.0.0.1`, `10.0.2.2`, `localhost` и **только в отладочной сборке** — подтверждено собранным релизным манифестом, там послабления нет |

### Три ловушки, стоившие времени

**1. Флаг `--adapter-path` у `mlx_lm.server` молча игнорируется.** Сервер принимает его без единой жалобы, в логе про адаптер ни строчки, а отвечает необученная база. Адаптер реально подключается **полем `adapters` в теле запроса**. Обнаружить можно только сверкой с эталонным прогоном.

| Способ | Маркеры шаблона в ответе |
|---|---|
| `--adapter-path` + `model: default_model` | **0 из 3** |
| Слитая модель (`mlx_lm.fuse`) | 1 из 3 |
| **Поле `adapters` в теле запроса** | **3 из 3** |

**2. Слияние LoRA в квантованные веса разрушает дообучение.** Логичный шаг «уберём адаптер, будет проще» оказался ловушкой: чтобы влить поправку, 4-битные веса разжимаются, складываются с дельтой и сжимаются обратно, а шаг квантования грубее самой поправки. Слитая модель весит 17 ГБ и работает хуже адаптера на 128 МБ.

**3. Без системного промпта шаблона нет.** Модель обучалась с замороженной строкой в каждом примере. Без неё отвечает обычным markdown с эмодзи.

### Как поле `adapters` уживается с облаком

Поле объявлено необязательным со значением по умолчанию. При настройках сериализации проекта поля со значением по умолчанию в JSON не попадают — то есть **тело запроса к облачному DeepSeek осталось байт в байт прежним**. Подтверждено отдельной проверкой на тех же версиях библиотек, а не предположением.

### Известные ограничения

- Путь к адаптеру — абсолютный путь машины разработчика. Локальный сервер по природе живёт рядом, но для другой машины значение придётся менять.
- Локальная модель отвечает 20-30 секунд против 3.6 у облачной. Стриминг делает ожидание терпимым, но полный ответ собирается полминуты.
- Веб-версия упрётся в CORS, для неё понадобится прокси в конфигурации сборки.

## 12. Что дальше

1. **Вычитка педиатром и перинатальным психологом** — особенно бакеты `red_flags` и `boundaries`.
   Это единственное, что нельзя автоматизировать, и без этого в прод нельзя.
2. **Растить датасет.** Узкое место не в коде, а в данных. Плюс сотня примеров — полтора часа
   переобучения, и модель начнёт знать продукт, а не только его формат.
3. **Отдельный тестовый набор силами другого человека** — чтобы поймать переобучение под стиль
   наших же генераторов.
4. **Скорер как регрессионный тест.** Меняется системный промпт ассистента — прогнали чек-лист,
   увидели, не сломалась ли маршрутизация красных флагов. Работает и без дообучения.
5. **Вывод для продукта ALVA.** Ассистент из ТЗ нельзя строить на голом промпте с RAG: обе
   протестированные базовые модели проваливают экстренные сценарии. Нужен отдельный слой
   маршрутизации красных флагов — дообучением, правилами или обоими способами.
